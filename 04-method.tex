\section{Overview: One Framework, One Swappable Slot}
\label{sec:method:overview}

The method of this thesis separates the experimental framework from the
spatial operators evaluated inside it. The aim is to find out which
properties a model needs in order to predict GA progression. Answering
that question requires a controlled comparison. If every candidate
architecture came with its own training pipeline, differences in data
handling, time representation or optimisation would be confounded with
the architectural differences under test. A single pipeline is therefore
fixed, and it provides one swappable slot for the update operator
$f_\theta$. The operator placed in this slot is the only component that
changes between experiments.

Everything outside the slot is held fixed. The input is the eleven-channel
state on the $49 \times 1024$ grid of Chapter~\ref{ch:data}. Time is
handled by a single-step residual update conditioned on the interval
between visits (\S\ref{sec:method:dt-residual}). The loss, the training
curriculum, the optimiser, the epoch budget, the cross-validation folds,
the random seeds, the evaluation and the model selection rule are shared
by every run. A backbone placed in the slot contains architecture only. It
receives the current state and its conditioning inputs in a common batch
format, and it returns the full predicted next state. It may not change the
optimisation loop or carry training settings of its own. A separate
pipeline per architecture would reintroduce exactly the confounds the
design is meant to remove.

Nine settings of the slot, spanning six architecture classes, are run
through this pipeline. They are a message-passing graph neural network on
two different graphs --- an index-space nearest-neighbour graph and a
dilated stencil at the physical scale of the lesion, the latter being the
canonical configuration of this thesis; a U-Net at a matched parameter
count and at a much larger capacity; a Fourier Neural Operator, alone and
with a small local convolutional bypass; a graph U-Net; and a Finite
Element Network, in a free-form version and with an explicitly learned
transport term. A fixed-step Runge--Kutta wrapper can be placed around any
of these operators, and a per-pixel model with no spatial context marks the
lower floor. All arms are parameter-matched to the canonical
configuration's 67\,147 parameters within a narrow band, except for two
deliberate controls. The matching is described in~\S\ref{sec:method:family}.

\section{The Fixed Framework}
\label{sec:method:framework}

This section defines what every arm shares: the time handling and the
tensor layout of the state. A further shared choice concerns the input
itself. Every operator receives exactly one visit and predicts the state at
the next visit. It sees the current state, the interval to the next visit
and the patient covariates, but no earlier visits. It has no memory of the
trajectory so far.

Two reasons support this design. First, the clinical sequences are short,
with five to thirteen visits per eye (\S\ref{sec:data:dataset}). Using
several past visits as input would leave fewer visits available as
prediction targets. Second, the framework predicts strictly one step at a
time. The original MP-PDE predicts several future steps in one forward pass
(temporal bundling, \S\ref{sec:background:mp-pde}). Here, this is removed.
The optional moving mesh of \S\ref{sec:method:mmpde} is computed from a
single state, so a mesh built at the start of a multi-step window would no
longer reflect the lesion at the later steps. The shared loss and
curriculum are defined in~\S\ref{sec:method:training}, and the shared
evaluation in~\S\ref{sec:experiments:protocol}.

\subsection{\texorpdfstring{$\Delta t$}{Delta t}-Conditioned Residual Formulation}
\label{sec:method:dt-residual}

The original neural PDE solvers use a fixed time step and receive the
absolute time as an input feature. The clinical data offers neither. Visits
occur at irregular intervals, and patients share no common time origin. The
absolute time is therefore replaced by the interval between two
consecutive visits, $\Delta t$, measured in years (\S\ref{sec:data:temporal}).

The transition from the current state $u_t$ to the next state
$u_{t+\Delta t}$ is written as a residual update scaled by the interval:
\begin{equation}
  u_{t+\Delta t} \;=\; u_t \;+\; \Delta t \cdot
  f_\theta\!\left(u_t,\, \Delta t,\, \mathbf{z}\right),
  \label{eq:method:residual-update}
\end{equation}
where $f_\theta$ is the operator in the swappable slot and $\mathbf{z}$
denotes the patient covariates. $\Delta t$ therefore enters twice. It is an
input feature of the network, so the operator can adapt its output to the
length of the interval. It is also the multiplier of the network output.

This form has a useful limit. As $\Delta t$ approaches zero, the predicted
change vanishes and the prediction collapses to $u_{t+\Delta t} = u_t$.
For two visits very close in time, the model thus predicts no change. The
leading $u_t$ term is also a deliberate prior. Consecutive visits are
almost identical, because GA changes slowly relative to the rest of the
retinal state. Passing the current state through unchanged relieves the
network of reproducing the whole state. It only has to model the change
over the interval. The output of $f_\theta$ is signed and unbounded, so the
model can also predict a shrinking lesion. No monotonic-growth constraint is
imposed; the prior rests on slow change alone.

The final layer of every operator's output head is initialised to zero,
weights and bias alike. Before training, $f_\theta$ therefore outputs zero
for every input, and Equation~\eqref{eq:method:residual-update} reduces to
exact persistence. Every arm starts from the same function.

Equation~\eqref{eq:method:residual-update} has the form of an explicit Euler
step (\S\ref{sec:background:pde-solvers:time}) and generalises the residual
update of MP-PDE (\S\ref{sec:background:mp-pde}) to a variable step. This
resemblance needs a caution.

The Euler form does not by itself make $f_\theta$ a time derivative or a
rate of change. A network trained with this update need not be a consistent
discretisation of any continuous-time system (Chen et al., 2018; Ott et
al., 2021). This thesis therefore does not assume such a reading. Whether
any of the models behaves as a continuous-time system is tested separately
in Chapter~\ref{ch:experiments}.

\subsection{Multi-Channel State Propagation}
\label{sec:method:multichannel}

The framework carries the full eleven-channel state through every
component. As defined in~\S\ref{sec:data:state}, the state consists of one
binary mask channel and ten layer-boundary depth channels. This subsection
covers only how these channels are laid out and moved as tensors.

Each window stores its input and target state with the layout
$(C, N, K) = (11, 50\,176, 1)$, where $C$ is the number of channels, $N$
the number of grid nodes and $K$ the number of time steps. At run time, a
batch of $B$ graphs is flattened into a node-feature matrix of shape
$(B \cdot N,\; C \cdot K) = (B \cdot 50\,176,\; 11)$. The feature axis is
ordered channel-major and time-minor. The node axis is ordered row-major
over the $49 \times 1024$ grid.

Operators that work on images, such as the convolutional arms
of~\S\ref{sec:method:family}, need the state in the image layout
$(B, C, 49, 1024)$. There is only one valid way to obtain it: the matrix is
first viewed as $(B, N, C, K)$, and the axes are then permuted. A direct
reshape to the image shape produces a tensor of the right size, but it
scrambles the channels across the grid and raises no error. The inverse
mapping follows the same rule in reverse.

All eleven channels are both input and output of the operator. The mask
channel is the clinical target, and the ten layer channels are auxiliary
targets. Each output channel receives its own independent prediction; for
the graph solver, this is guaranteed by the full-rank decoder
of~\S\ref{sec:method:mppde:arch}. The loss weights the mask channel more
heavily than the layer channels, with the weights set
in~\S\ref{sec:method:training}. The mesh mover of~\S\ref{sec:method:mmpde}
reads only the mask channel to compute the moved mesh. The network branch
that operates on the moved mesh still processes all eleven channels.


\section{Backbone I: The GA-Adapted Graph Solver}
\label{sec:method:mppde}

The first backbone is the encode--process--decode message-passing network
of MP-PDE (\S\ref{sec:background:mp-pde}), adapted to the clinical setting.
It is not a privileged arm. It is described in more depth than the others
because this project built it rather than imported it, and because several
of its design decisions --- the time handling, the output layer and the
strict one-step prediction --- became part of the shared framework. The
same network class is used for both branches of the moving-mesh extension
of~\S\ref{sec:method:mmpde}. Temporal bundling is removed entirely, for the
reasons given in~\S\ref{sec:method:framework}. \S\ref{sec:method:mppde:arch}
describes the architecture, \S\ref{sec:method:graph} the graph it operates
on, and \S\ref{sec:method:mppde:diff} summarises the departures from the
original.

\subsection{Architecture}
\label{sec:method:mppde:arch}

The forward pass consists of an encoder, a number of message-passing
rounds and a decoder. The notation follows~\S\ref{sec:background:mp-pde}.
Each node $i$ carries the normalised eleven-channel state $u_i$ and its
physical position $(x_i, y_i)$ in millimetres. The positions enter the
network divided by the domain size, as $(x_i / L_x,\, y_i / L_y)$.

Each node also receives a conditioning vector $\mathbf{c}_i$. In the
canonical configuration it has three entries: the interval $\Delta t$ in
years, the z-scored age and the sex of the patient. All three are
graph-level quantities, broadcast to every node of the graph. An optional
learned layer embedding can be appended (\S\ref{sec:method:encoder}); it is
switched off in the canonical configuration. The conditioning vector fills
the slot that the equation feature vector $\theta_{\text{PDE}}$ occupies in
the original. No governing equation or coefficients are known for GA, so
the interval and the covariates take this place. As in the original, the
vector is injected at three points: the encoder input, every message and
every node update.

The encoder maps the concatenated node input to a hidden vector,
\begin{equation}
  f_i^{0} \;=\; \epsilon\!\left(\left[u_i,\; x_i / L_x,\; y_i / L_y,\;
  \mathbf{c}_i\right]\right),
  \label{eq:method:encoder}
\end{equation}
where $\epsilon$ consists of a linear layer, layer normalisation, a ReLU
activation, a second linear layer and a final layer normalisation, with no
activation after it.

Each message-passing round $m$ computes a message along every edge from
node $j$ to node $i$ and then updates node $i$:
\begin{align}
  m_{ij}^{m} &\;=\; \phi\!\left(f_i^{m},\; f_j^{m},\; u_i - u_j,\;
    \Delta\mathbf{p}_{ij},\; \mathbf{c}_i\right),
  \label{eq:method:message}\\
  f_i^{m+1} &\;=\; \mathrm{LN}\!\left(f_i^{m} + \psi\!\left(f_i^{m},\;
    \frac{1}{|\mathcal{N}(i)|}\sum_{j \in \mathcal{N}(i)} m_{ij}^{m},\;
    \mathbf{c}_i\right)\right).
  \label{eq:method:update}
\end{align}
Here $\Delta\mathbf{p}_{ij}$ is the offset between the normalised positions
of the two nodes, $\mathcal{N}(i)$ is the set of neighbours of node $i$, and
$\mathrm{LN}$ denotes layer normalisation. The message function $\phi$ and
the update function $\psi$ each consist of two linear layers, each followed
by a ReLU activation. As in the original, the state difference $u_i - u_j$
lets the message act as a learned local difference operator. Every round
receives the raw state, the positions and the conditioning vector again, so
this information is available at every depth. As in the original, which
uses skip connections in its message-passing layers, each update ends in a
residual connection followed by a normalisation layer; only the type of
normalisation differs. The canonical configuration aggregates messages by their
mean, as written in Equation~\eqref{eq:method:update}. The arm on the
index-space graph instead concatenates the mean and the maximum of the
messages. The canonical configuration uses two message-passing rounds and
a hidden width of 64. This capacity is a configuration choice based on
experiments reported in Chapter~\ref{ch:experiments}.

% TODO: cite Ba2016 (Ba, Kiros & Hinton, "Layer Normalization",
% arXiv:1607.06450, 2016)
% TODO: cite Ioffe2015 (Ioffe & Szegedy, "Batch Normalization:
% Accelerating Deep Network Training by Reducing Internal Covariate
% Shift", ICML 2015, arXiv:1502.03167)
All normalisation layers are per-node layer normalisations (Ba et al.,
2016). Each node is normalised over its own feature vector. No running
statistics are kept, and no nodes or graphs are coupled, so the operator is
identical in training and in evaluation. This matters because of the
training curriculum of~\S\ref{sec:method:training}, which rolls the model
forward on its own predictions without gradients but in training mode.
Batch normalisation (Ioffe \& Szegedy, 2015) would normalise these drifted
states with the statistics of the current batch. This would erase the very
perturbation the curriculum is meant to expose the model to. It would also
write the drifted statistics into the running estimates that evaluation
later uses. Before this change, training and evaluation measurably behaved
as two different operators. A graph-level variant that normalises a whole
batch as one graph was avoided for the same reason, because it would couple
the samples of a batch.

The decoder maps the final hidden vector $f_i^{M}$ to one output per
channel. It consists of a linear layer, layer normalisation and a ReLU,
applied twice, followed by a final linear layer to $C \cdot K = 11$
outputs. The final layer is bare, without normalisation or activation,
because the output is a signed and unbounded residual. On the uniform
branch, the node update is then
$u_i + \Delta t \cdot \delta(f_i^{M})$, where $\delta$ denotes the decoder;
this is Equation~\eqref{eq:method:residual-update} at node level.

This decoder replaces the convolutional output head of the original. That
head treats the final hidden vector of a node as a temporal signal and
convolves along it to emit the $K$ bundled future steps
\citep{Brandstetter2022}. With $K = 1$ and eleven channels, the head reduced
the hidden vector to a single scalar per node and then expanded that scalar
linearly to all eleven channels. The eleven outputs were therefore perfectly
collinear, a rank-1 bottleneck. The head also required a hidden width of at
least 113. The replacement gives every channel an independent output and
restores full rank. Its final layer is initialised to zero on the uniform
branch, which yields the persistence start
of~\S\ref{sec:method:dt-residual}. On the correction branch of the moving
mesh it must not be, for reasons given in~\S\ref{sec:method:dual}.

\subsection{Graph Construction on an Anisotropic Grid}
\label{sec:method:graph}

The graph on which messages travel turns out to be the most consequential
design decision of the graph solver. The modelling grid has 49 rows and
1024 columns, or 50\,176 nodes. Rows are 0.12118\,mm apart, while columns
are only 0.00568\,mm apart (\S\ref{sec:data:spatial}). Along a row, the
nodes are therefore about 21 times denser than across rows. The node
positions are stored in physical millimetres.

A $k$-nearest-neighbour graph built on these physical positions fails. The
twelve physically nearest neighbours of every node all lie in its own row:
measured over the grid, 100\,\% of the edges connect nodes in the same row
and none cross rows. Message passing on such a graph runs along rows only.
No information can cross from one row to the next at any network depth, and
the two-dimensional retina falls apart into 49 independent one-dimensional
strands.

Building the graph on integer grid indices instead of physical coordinates
restores two-dimensional connectivity. With $k = 12$, and without
self-loops, the neighbourhood of an interior node is exactly the
index-space disc of squared radius four, a diamond of radius two. It
contains the four direct neighbours, the four diagonal neighbours and the
four neighbours two steps away along either axis. The resulting graph has
602\,112 directed edges; about 33\,\% connect nodes in the same row,
50\,\% nodes one row apart and 17\,\% nodes two rows apart. About 8.5\,\%
of the nodes (4\,276), on and next to the border of the grid, do not have
the full interior neighbourhood.

This index-space graph solves the connectivity problem, but its physical
reach is lopsided. A neighbourhood that is symmetric in grid steps inherits
the 21:1 anisotropy of the grid. One hop reaches about $\pm 0.25$\,mm
across rows but only about $\pm 0.011$\,mm along a row. After the two
message-passing rounds of the canonical configuration, a node has received
information from at most four columns away, about $\pm 0.023$\,mm along the
row.

This reach can be compared with the scale on which the lesion changes.
Between two visits 180 days apart, the GA front advances a median of about
12 columns, or roughly 0.07\,mm. The upper quartile is 17 columns and the
90th percentile 23 columns. A single hop along a row therefore covers only
a small fraction of the distance the front typically moves between two
visits.

The dilated stencil is designed to close this gap
(Figure~\ref{fig:method:stencils}). Each interior node is connected to the
nodes at row offsets $\{-1, 0, +1\}$ and column offsets
$\{0, \pm 7, \pm 14, \pm 21\}$, excluding the node itself: 20 neighbours in
total. One hop then reaches $\pm 0.121$\,mm across rows and
$\pm 0.119$\,mm along a row. The physical reach is nearly equal on both
axes, at about 0.12\,mm per hop. Along a row, one hop now spans 21 columns,
close to the 90th percentile of the per-visit front advance. The design
thus sets the reach from the physical scale of the lesion rather than
treating it as a free hyperparameter. Chapter~\ref{ch:experiments} tests
this choice against smaller and larger reaches.

The dilated stencil replaces only the edge set. The network, its weights
and every other component stay unchanged, and the stencil adds no
parameters. It is used on the uniform grid only. The nodes of the moved
mesh in~\S\ref{sec:method:mmpde} lie off the lattice, where a lattice
stencil is undefined, so that branch builds its own $k$-nearest-neighbour
graph on the moved positions (\S\ref{sec:method:dual}).

The two canonical configurations differ slightly in size, and the
difference comes from the aggregation, not from the graph. With the
dilated stencil and mean aggregation, the network has 67\,147 parameters;
the arm on the index-space graph, with concatenated mean and maximum, has
75\,339. The concatenation doubles the width of the aggregated message that
enters the update function. The same network on the dilated stencil with
mean-and-maximum aggregation also has 75\,339 parameters, and on the
index-space graph with mean aggregation also 67\,147.

\section{Backbone II: The Countermodel Family}
\label{sec:method:family}

The framework of~\S\ref{sec:method:framework} provides one slot for the
update operator $f_\theta$. This section describes every architecture other
than the graph solver of~\S\ref{sec:method:mppde} that occupies that slot.
Each of them is a comparison model --- a countermodel --- chosen to isolate
one property. A U-Net tests multiscale local detail. A Fourier Neural
Operator tests global spectral support without a local path, and a hybrid
adds a minimal local path to it. A graph U-Net separates the operator class
from the multiscale pyramid. Two truncated graph solvers test how much
spatial context is needed at all. A Finite Element Network adds an explicit
transport term. Finally, a Runge--Kutta wrapper changes the time integration
of any of these operators. Because all of them run in the same training
environment, differences between them can be attributed to the architecture
rather than to the training protocol.

\S\ref{sec:method:family:contract} states the interface every member
satisfies. \S\ref{sec:method:family:dense} describes the three dense grid
operators, \S\ref{sec:method:family:floors} the graph U-Net and the locality
floors, and \S\ref{sec:method:family:fen} the Finite Element Network.
\S\ref{sec:method:family:rk} describes the integration wrapper, and
\S\ref{sec:method:family:params} the parameter matching.

\subsection{The Backbone Contract}
\label{sec:method:family:contract}

Every member of the family satisfies the same interface. It is built from
the same metadata --- one time step, eleven state channels and two
covariates --- and it consumes the same batch. It returns the full next
state in the residual form of Equation~\eqref{eq:method:residual-update}:
the predicted residual is scaled by $\Delta t$ and added to the input
state. The final layer of every architecture is initialised to zero, so
every member starts training at exact persistence. Each module computes the
residual and the next state from one shared internal computation, so the
two cannot diverge. The integration wrapper of~\S\ref{sec:method:family:rk}
integrates exactly this residual.

No member uses a normalisation that keeps batch statistics. The reason is
the one given in~\S\ref{sec:method:mppde:arch}: the training curriculum
rolls the model forward on its own predictions in training mode, and batch
statistics would make training and evaluation behave as two different
operators. The loss, the curriculum, the optimiser, the computational
budget, the model selection and the random seeds are identical for every
member. The members differ in their architecture only.

The three operators that work on the image grid --- the U-Net, the Fourier
Neural Operator and the graph U-Net --- receive identical inputs. Each takes
sixteen input channels: the eleven state channels, $\Delta t$ broadcast as a
constant plane, the two covariates broadcast as constant planes, and two
coordinate ramps running from zero to one along each axis.
% TODO: cite Liu2018 (Liu, Lehman, Molino, Petroski Such, Frank, Sergeev &
% Yosinski, "An Intriguing Failing of Convolutional Neural Networks and the
% CoordConv Solution", NeurIPS 2018, arXiv:1807.03247)
The coordinate ramps follow the CoordConv construction of Liu et al.
(2018). Because the inputs are identical, a difference between these three
arms reflects the operator, not the information it receives.

The three grid operators and the Finite Element Network run as single-branch
models and without the layer encoder of~\S\ref{sec:method:encoder}. The
U-Net is therefore a like-for-like comparison with the single-branch graph
solver, not with the moving-mesh variant of~\S\ref{sec:method:mmpde}. One
technical difference remains: the convolutional arms run their convolutions
at the default TF32 precision of the GPU, whereas the linear layers of the
graph solver run in standard 32-bit precision. The arms are therefore not
precision-matched (\S\ref{sec:method:implementation}).

\subsection{Dense Operators: U-Net, FNO and a Local-Kernel Hybrid}
\label{sec:method:family:dense}

% TODO: cite Ronneberger2015 (Ronneberger, Fischer & Brox, "U-Net:
% Convolutional Networks for Biomedical Image Segmentation", MICCAI 2015,
% arXiv:1505.04597)
The first dense operator is a U-Net (Ronneberger et al., 2015). The
original was designed for biomedical image segmentation. It consists of a
contracting and an expansive path. Each contracting step applies two
unpadded $3 \times 3$ convolutions, each followed by a ReLU, and then a
$2 \times 2$ max pooling with stride two; the number of feature channels
doubles at each downsampling step. Each expansive step upsamples, halves the
channels with an up-convolution, concatenates the correspondingly cropped
feature map from the contracting path, and applies two further $3 \times 3$
convolutions. A final $1 \times 1$ convolution maps to the output classes.
% TODO: cite Gupta2023 (Gupta & Brandstetter, "Towards
% Multi-spatiotemporal-scale Generalized PDE Modeling", TMLR 2023,
% arXiv:2209.15616)
Gupta and Brandstetter (2023) study modernised U-Nets as PDE surrogates and
attribute their strength to handling local and global information through
the down- and up-sampling paths.
% TODO: cite Salvi2025 (Salvi et al., "Deep Learning to Predict the Future
% Growth of Geographic Atrophy from Fundus Autofluorescence", Ophthalmology
% Science 5(2):100635, 2025)
In the GA domain, Salvi et al. (2025) predict future lesion growth with a
two-dimensional U-Net on fundus autofluorescence images.

The U-Net used here departs from the original in four ways. First, each
convolution is followed by group normalisation with a single group before
the ReLU; the original uses no normalisation.
% TODO: cite Wu2018 (Wu & He, "Group Normalization", ECCV 2018,
% arXiv:1803.08494)
With one group, group normalisation normalises each sample over all its
channels and positions and keeps no batch statistics (Wu \& He, 2018). With
nine such blocks --- an input stage, four downsampling and four upsampling
stages --- the network has 18 normalised convolution sites. Second, pooling
is anisotropic. The factors (rows, columns) are $(1, 2)$, $(1, 2)$,
$(2, 2)$ and $(2, 2)$, so the grid shrinks from $49 \times 1024$ through
$49 \times 512$, $49 \times 256$ and $24 \times 128$ to $12 \times 64$. Rows
are pooled four times and columns sixteen times, which reduces the 21:1
aspect of the grid to about 5:1 without removing it. The schedule was
deliberately not tuned further, because a comparison model whose geometry
has been optimised against this dataset would be a weaker control, not a
stronger one. Third, upsampling is nearest-neighbour instead of an
up-convolution, and the output has the grid size of the input. Fourth, the
final $1 \times 1$ layer is zero-initialised and returns a residual rather
than class scores. Two widths are used: a base width of five gives
83\,081 parameters (the parameter-matched arm), and a base width of 32 gives
3\,354\,347 (the capacity control).

% TODO: cite Li2021 (Li, Kovachki, Azizzadenesheli, Liu, Bhattacharya,
% Stuart & Anandkumar, "Fourier Neural Operator for Parametric Partial
% Differential Equations", ICLR 2021, arXiv:2010.08895)
The second dense operator is the Fourier Neural Operator (FNO) of Li et al.
(2021). The input is first lifted to a wider representation by a local
map. Each layer then combines a local linear transform with a non-local
integral operator and applies a nonlinearity. The integral operator
transforms its input to Fourier space, multiplies the retained low modes by
learned complex weights, and transforms back. Modes above a threshold are
truncated; both the low positive and the low negative frequencies are kept.
A local projection maps the result to the output. The paper shows that the
Fourier layers are invariant to the discretisation, and that truncation does
not limit the output to the retained modes, because the nonlinearities and
the projection recover higher frequencies. For its two-dimensional problems,
the original uses four Fourier layers, ReLU activations with batch
normalisation, 12 modes per dimension and a width of 32. It notes that the
local linear term helps the model handle non-periodic boundaries.

The FNO used here keeps four blocks, each a spectral convolution plus a
pointwise $1 \times 1$ path, and departs from the original in the
following respects. It uses GELU activations between blocks instead of ReLU,
and no normalisation. It retains 14 modes per axis instead of 12, and its
width is 5 instead of 32, which gives 79\,160 parameters. The output passes
through a $1 \times 1$ convolution to 32 channels, a GELU and a
zero-initialised $1 \times 1$ projection. The domain here is a crop, not a
periodic physical domain (\S\ref{sec:data:spatial}). This thesis therefore
zero-pads the field by about one eighth per axis before the transform, from
$49 \times 1024$ to $56 \times 1152$, and crops it back after the spectral
blocks; the original relies on the local linear term instead and does not
pad. The mode count follows from the geometry. The physical domain is nearly
square ($5.94 \times 5.82$\,mm), so equal mode counts give nearly equal
physical bandwidth on both axes --- the property the index-space graph
of~\S\ref{sec:method:graph} lacks. Dividing the padded extent by the highest
retained mode index, 13, gives a finest retained wavelength of about
0.52\,mm across rows and 0.50\,mm along columns. The mode count was not
ablated.

The third dense operator is a local-kernel hybrid.
% TODO: cite LiuSchiaffini2024 (Liu-Schiaffini, Berner, Bonev, Kurth,
% Azizzadenesheli & Anandkumar, "Neural Operators with Localized Integral
% and Differential Kernels", ICML 2024, arXiv:2402.16845)
Liu-Schiaffini et al. (2024) observe that global operations in Fourier
space are prone to over-smoothing and may miss local details. They add
localised operators in parallel to the Fourier layers and the pointwise
path. Their differential kernels subtract the kernel mean and rescale by the
reciprocal grid width, so that the convolution converges to a differential
operator as the grid is refined; their localised integral kernels use
discrete-continuous convolutions. The hybrid used here is the simplest
instance of this idea. It widens the pointwise $1 \times 1$ path of each FNO
block to an unconstrained $3 \times 3$ convolution, so a local path runs in
parallel with the spectral one. Unlike the original, it operates at a single
training resolution, without mean subtraction, without rescaling and without
discrete-continuous convolutions; it is therefore not the
resolution-consistent operator of that paper. The spectral path keeps
global support and the local path gains one ring of neighbours, at a cost
of 800 parameters (79\,960 in total). With a kernel size of one, the model
reduces exactly to the plain FNO.

\subsection{The Graph U-Net and the Locality Floors}
\label{sec:method:family:floors}

The graph U-Net sits between the U-Net and the graph solver. It is the
U-Net of~\S\ref{sec:method:family:dense} with every $3 \times 3$ convolution
replaced by one message-passing layer on the 8-connected grid graph, which
links each pixel to its horizontal, vertical and diagonal neighbours. The
pyramid, the pooling schedule, the channel schedule, the 18 normalised
sites, the nearest-neighbour upsampling, the skip connections, the
zero-initialised head and the input channels are all unchanged. Each
message is computed by one shared layer --- a linear map followed by a ReLU
--- applied to the two hidden states and the row and column offsets between
them, at each of the eight offsets. Neighbours outside the grid are left out
of the mean. This is mean-aggregation message passing on the 8-neighbour
graph. The model has 72\,713 parameters.

Against the U-Net, this architecture isolates the operator class at a fixed
multiscale pyramid. Against the graph solver of~\S\ref{sec:method:mppde}, it
isolates the pyramid at a fixed operator class.
% TODO: cite Gilmer2017 (Gilmer, Schoenholz, Riley, Vinyals & Dahl,
% "Neural Message Passing for Quantum Chemistry", ICML 2017,
% arXiv:1704.01212)
One caveat applies. A message function that is shared across offsets and
receives the offset as an input is the standard message-passing
construction (Gilmer et al., 2017), but it is not a strict superset of a
$3 \times 3$ convolution, which has a separate weight matrix for every
offset. The comparison therefore probes the question whether a convolution
is a one-hop graph layer in one direction only.
% TODO: cite Gao2019 (Gao & Ji, "Graph U-Nets", ICML 2019,
% arXiv:1905.05178)
The name is reused: Gao and Ji (2019) introduced Graph U-Nets that pool a
general graph by selecting nodes with a learned projection score. That
pooling is not used here; the pyramid is an ordinary image pyramid.

Two further arms test how much spatial context is needed at all. Both are
the graph solver on the index-space $k$-nearest-neighbour graph
of~\S\ref{sec:method:graph} with fewer message-passing rounds, so neither
needs a separate module. The one-hop floor uses a single round at width 64,
so each node sees exactly one ring of neighbours; it has 45\,067 parameters.
The per-pixel floor uses no message passing at all. Each node's next state
then depends only on its own state and its conditioning inputs, and the
model has no spatial context; it has 14\,795 parameters. Together with the
two-round index-space arm, they form a locality ladder of zero, one and two
rounds.

\subsection{The Finite Element Network}
\label{sec:method:family:fen}

% TODO: cite Lienen2022 (Lienen & Günnemann, "Learning the Dynamics of
% Physical Systems from Sparse Observations with Finite Element Networks",
% ICLR 2022, arXiv:2203.08852)
The Finite Element Network (FEN) of Lienen and G\"unnemann (2022) builds the
update from a finite-element discretisation of an unknown PDE. It is the only
member of the family whose output is defined as a time derivative by
construction rather than as a next state. This is a property of the
architecture. It is not a claim that the trained model behaves as a valid
continuous-time system, which is tested in Chapter~\ref{ch:experiments}.

The original uses a Galerkin method with the P1 basis of piecewise-linear
hat functions, by default on a Delaunay triangulation of the observation
points. The resulting system involves the mass matrix of inner products
between basis functions, which is lumped by row-wise summation --- a
standard approximation for time-dependent problems that makes its inversion
trivial. The inner products are factored so that a network, the free-form
term, predicts one coefficient per cell, vertex and feature from the time,
the cell centre, the local vertex coordinates and the vertex features. The
transport variant, T-FEN, adds a convection term. It starts from the
conservative form $-\nabla \cdot (v u)$, applies the product rule and
assumes a divergence-free velocity, which leaves the advective form
$-v \cdot \nabla u$. A second network predicts one velocity per cell and
feature; since the velocity is constant within each cell, it is
divergence-free there, but not across cells. Both networks are tanh MLPs,
and the resulting ODE is solved with the adaptive dopri5 solver.

The FEN used here triangulates the regular grid by splitting every grid
cell into two right triangles, which gives 98\,208 triangles over the
50\,176 nodes; each node belongs to one, two, three or six triangles. The
mass matrix is lumped as in the original. On this equal-area lattice the
lumped assembly is exactly a mean over the triangles adjacent to a node.
On a uniform mesh, the FEN is therefore a message-passing network over
triangle hyperedges with mean aggregation, and the finite-element machinery
only makes a difference at the boundary. The free-form term is a tanh MLP
of depth four and width 96, without normalisation and with a
zero-initialised head. It receives the three vertex states of a triangle, a
triangle-type indicator for the two triangle orientations, the covariates
and optionally the normalised triangle centre, and it outputs one
coefficient per vertex and channel.

The transport term is a second MLP that predicts one velocity per triangle
and channel, in millimetres per year. The assembled operator is the
advective form $-v \cdot \nabla u$ with a velocity that is constant within
each triangle, as in the original. Neither the original nor this
implementation makes the velocity divergence-free across triangles, so
reading it as a physical advection speed rests on an assumption the model
does not enforce globally. The gradient coefficients are assembled in grid
units, so the 21:1 axis imbalance never reaches the MLPs; only the velocity
conversion uses millimetres. No flux term is assembled at the edge of the
domain, so the crop border carries a natural, no-flux boundary condition by
construction --- a statement about the crop, not about the anatomy
(\S\ref{sec:data:spatial}). The transport term runs on its own coarser mesh,
built on every seventh column (97\,632 triangles), while the free-form term
uses the full-resolution mesh. This coarser mesh is the finite-element
counterpart of the dilated stencil of~\S\ref{sec:method:graph}.

The implementation departs from the original in the following points. A
regular lattice replaces the Delaunay triangulation. A triangle-type
indicator replaces the local vertex coordinates, which on this lattice take
only two forms. The covariates are added as inputs. The time is not an
input, so the learned dynamics are autonomous, a variant the original paper
explicitly allows. Integration uses a fixed-step scheme instead of the
adaptive dopri5 solver. The advective form and the per-cell velocity are the
same as in the original.

One evaluation of the time derivative only couples nodes that share a
triangle, so spatial reach has to come from sub-steps. The FEN is therefore
always run inside the Runge--Kutta wrapper of~\S\ref{sec:method:family:rk},
with classical RK4 and a fixed physical step of 45 days; $\Delta t$ sets
only the integration horizon. The step is constrained by stability. On the
lattice, the assembled transport operator is a skew-symmetric
central-difference stencil whose interior spectrum is purely imaginary. An
explicit Euler step therefore amplifies every mode for any non-zero velocity,
and the second-order midpoint and Heun schemes have no stability interval on
the imaginary axis. Classical RK4 has one, $|\lambda| h \leq 2\sqrt{2}
\approx 2.83$.
% TODO: cite Courant1928 (Courant, Friedrichs & Lewy, "Über die partiellen
% Differenzengleichungen der mathematischen Physik", Mathematische Annalen
% 100(1):32-74, 1928)
The implementation checks the Courant number $C = |v| h$ per sub-step
against this limit, in the spirit of the classical stability condition of
Courant et al. (1928). The limit is monitored, not enforced during training.
% TODO: resolve the RK4 Courant bound for the assembled transport stencil
% (2.8 as implemented vs ~2.4 derived from the stencil's spectral radius of
% about 1.1-1.2).
Its exact value also depends on the spectral radius of the assembled
stencil, which was estimated at about 1.1 to 1.2 per unit velocity and step
and would place the bound nearer $C \approx 2.4$.

The T-FEN has 68\,503 parameters, of which 34\,785 belong to the free-form
term and 33\,718 to the transport head. The free-form-only control removes
the transport head at the same width and has 34\,785 parameters. This
control is therefore not parameter-matched to the T-FEN: the two differ by a
factor of 1.97.
% TODO: a parameter-matched free-form FEN control (width ~139) has not been
% run.
A matched free-form control, at a width of about 139, was not run.

\subsection{Fixed-Step Runge--Kutta Integration}
\label{sec:method:family:rk}

The Runge--Kutta wrapper is not a backbone. It takes the residual $f_\theta$
of any backbone and integrates it over each graph's own interval with an
explicit Runge--Kutta scheme, stored as a Butcher tableau. It adds no
parameters. All reported runs use classical fourth-order Runge--Kutta
(RK4).
% TODO: cite Butcher1987 (Butcher, "The Numerical Analysis of Ordinary
% Differential Equations: Runge-Kutta and General Linear Methods", Wiley
% 1987)
% TODO: cite Hairer1993 (Hairer, Nørsett & Wanner, "Solving Ordinary
% Differential Equations I: Nonstiff Problems", Springer, 2nd revised ed.
% 1993)
The schemes follow the standard definitions (Butcher, 1987; Hairer et al.,
1993).

The step is set per graph. It is either the interval divided by a number of
sub-steps, $h = \Delta t / n$, or it follows from a physical step length in
days, with the number of sub-steps rounded up from the ratio of the interval
to that length. An eye is therefore integrated with the same step whether it
is batched with others or evaluated alone. Graphs with shorter intervals
finish early and then take zero-length steps until the longest interval in
the batch is complete.

By default the wrapper integrates an autonomous field. The $\Delta t$ entry
of the conditioning vector is set to zero inside the wrapper, so $f_\theta$
becomes a right-hand side that does not depend on the interval, and
$\Delta t$ only sets the integration horizon. The positions, the graph edges
and the covariates of a graph stay fixed across the stages of one step.
% TODO: cite Chen2018 (Chen, Rubanova, Bettencourt & Duvenaud, "Neural
% Ordinary Differential Equations", NeurIPS 2018, arXiv:1806.07366)
This is the reading under which the wrapped model is a Neural ODE in the
sense of Chen et al. (2018). If the sub-step length is fed in place of zero,
the wrapper instead acts as a learned Runge--Kutta integrator, which reduces
to the canonical operator for a single Euler step. The wrapper applies to
single-branch models only and requires the $\Delta t$-multiplied residual
form of Equation~\eqref{eq:method:residual-update}. As a unit check, the
observed convergence orders on the test problem $\mathrm{d}u / \mathrm{d}t =
-\lambda u$ are 0.99, 2.04, 2.04 and 4.35 for the Euler, midpoint, Heun and
RK4 schemes, close to their nominal orders of one, two, two and four.

% TODO: cite Ott2021 (Ott, Katiyar, Hennig & Tiemann, "ResNet After All:
% Neural ODEs and Their Numerical Solution", ICLR 2021, arXiv:2007.15386)
% TODO: cite Krishnapriyan2023 (Krishnapriyan, Queiruga, Erichson &
% Mahoney, "Learning continuous models for continuous physics",
% Communications Physics 6:319, 2023, arXiv:2202.08494)
Because any trained backbone can be integrated with different schemes and
step counts after training, the wrapper also enables a solver-invariance
test. Ott et al. (2021) show that a model trained with an overly coarse step
can reach high accuracy and still lose its interpretation as an ODE; they
test this by evaluating the trained model with solvers of equal or smaller
discretisation error and checking whether its predictions stay the same.
Krishnapriyan et al. (2023) make the same point for learned models of
physical systems. The test and its outcome are reported in
Chapter~\ref{ch:experiments}.

\subsection{Parameter Matching}
\label{sec:method:family:params}

Every member of the family is matched in size to the canonical graph solver
of~\S\ref{sec:method:graph}, which has 67\,147 parameters. The widths are
chosen so that each arm comes as close to this count as its width
granularity allows. The principle follows \citet{Hu2024}, who compare MM-PDE
with a deepened and widened GNN of similar parameter count, so that gains
cannot be attributed to extra parameters. Table~\ref{tab:method:params}
lists every configuration. All architecture arms lie within a factor of
1.25 of the reference. The one-hop floor lies below this band because it is
a rung of the locality ladder of~\S
ef{sec:method:family:floors}, not an
architecture arm.

Two deliberate controls lie outside this band and bound the parameter
question from both sides. The width-32 U-Net has about 50 times the
parameters of the canonical configuration and tests whether capacity alone
changes the picture. The per-pixel floor has about a fifth of them and
marks what a model without spatial context can do.

One comparison is not matched. The free-form FEN control has 34\,785
parameters, half the reference and a factor of 1.97 below the T-FEN it
controls, because it is the T-FEN with the transport head removed
(\S\ref{sec:method:family:fen}). A matched free-form control was not run.
The Runge--Kutta wrapper adds no parameters to any backbone.
