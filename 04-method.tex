\label{sec:method:overview}

This chapter answers the first part of the research question: what kind
of framework the forecast needs. The framework defines everything except
the operator: how the state is represented, how the elapsed time
between visits enters the prediction, and how every model is trained and
evaluated. Holding these parts fixed removes them as confounding factors
when operators are compared. If every candidate architecture came with its
own training pipeline, differences in data handling, time representation
or optimisation would be confounded with the architectural differences
under test. A single pipeline therefore provides one swappable slot for
the operator $f_\theta$, the only component that changes between
experiments. Each setting of the slot is referred to below as an
\emph{arm} of the comparison.

Everything outside the slot is held fixed. The input is the eleven-channel
state on the $49 \times 1024$ grid of Chapter~\ref{ch:data}. Time is
handled by a single-step residual update conditioned on the interval
between visits (\S\ref{sec:method:dt-residual}). The loss, the training
curriculum, the optimiser, the epoch budget, the cross-validation folds,
the random seeds, the evaluation and the model selection rule are shared
by every run. An operator placed in the slot contains only its
architecture. It receives the current state and its conditioning inputs in
a common batch format, and it returns the full predicted next state. It may
not change the optimisation loop or carry training settings of its own.

The operators run through this pipeline are a message-passing graph
neural network (GNN) on two different neighbourhood graphs
(\S\ref{sec:method:graph}), a U-Net, a Fourier Neural Operator (FNO) and a
hybrid Finite Element Network (FEN). Several of these are run in more than
one variant (\S\ref{sec:method:family}). The GNN on one of the two graphs
is the \emph{canonical} model of this thesis. It is the reference
configuration: the ablations of the framework in
Chapter~\ref{ch:experiments} are run on it, and the other arms are matched
to its 67\,147 parameters within a narrow band; the matching and its
exceptions are described in~\S\ref{sec:method:family:params}. A
fixed-step Runge--Kutta wrapper can be placed around any of these
operators. A per-pixel model with no spatial context serves as the lowest
reference point of the comparison (\S\ref{sec:method:family:floors}).

\section{The Fixed Framework}
\label{sec:method:framework}

This section defines what every arm shares: the input, the time handling
(\S\ref{sec:method:dt-residual}), the tensor layout of the state
(\S\ref{sec:method:multichannel}), the conditioning inputs
(\S\ref{sec:method:covariates}), the objective
(\S\ref{sec:method:training:loss}), the training curriculum
(\S\ref{sec:method:training:curriculum}) and the optimisation
(\S\ref{sec:method:training:optim}). These parts are the same for every
operator of the survey; the shared evaluation follows
in~\S\ref{sec:experiments:protocol}.

Every operator receives exactly one visit, without earlier visits as
input, and predicts the state at the next visit. With five to thirteen
visits per eye (\S\ref{sec:data:dataset}), using several past visits as
input would leave fewer visits as prediction targets; an operator with
memory of the trajectory is left for future work
(\S\ref{sec:discussion:future}). The framework also predicts one step at a
time. Some neural PDE solvers, such
as MP-PDE, predict several future steps in one forward pass (temporal
bundling, \S\ref{sec:background:neural-pde}), but not all of the operators
compared here support this. Bundling is therefore removed, so that every
operator makes the same kind of prediction.

\subsection{\texorpdfstring{$\Delta t$}{Delta t}-Conditioned Residual Formulation}
\label{sec:method:dt-residual}

Neural PDE solvers such as MP-PDE (\S\ref{sec:method:mppde}) use a fixed
time step and receive the absolute time as an input feature. The clinical data offers neither. Visits
occur at irregular intervals, and patients share no common time origin. The
absolute time is therefore replaced by the interval between two
consecutive visits, $\Delta t$, measured in years (\S\ref{sec:data:temporal}).

The update of the problem statement (\S\ref{sec:background:problem},
Equation~\eqref{eq:bg:problem-update}) writes the transition from the
current state $u_t$ to the next state $u_{t+\Delta t}$ as a residual update
scaled by the interval:
\begin{equation}
  u_{t+\Delta t} \;=\; u_t \;+\; \Delta t \cdot
  f_\theta\!\left(u_t,\, \Delta t,\, \mathbf{z}\right),
  \label{eq:method:residual-update}
\end{equation}
where $f_\theta$ is the operator in the swappable slot and $\mathbf{z}$
denotes the patient covariates. $\Delta t$ therefore enters twice. It is an
input feature of the network, so the operator can adapt its output to the
length of the interval. It is also the multiplier of the network output.

% Supervisor review 2, SV-4.3 (2026-10-17): "not entirely true as we don't
% know df/d delta t; put an assumption on lipschitz constant of f". The limit
% now states its assumption.
If $f_\theta$ stays bounded as $\Delta t$ approaches zero, the predicted
change $\Delta t \cdot f_\theta$ vanishes and the prediction collapses to
$u_{t+\Delta t} = u_t$. Because $\Delta t$ is also an input of $f_\theta$,
this is not automatic. It is guaranteed if $f_\theta$ is
Lipschitz-continuous in $\Delta t$ with a constant $L$, since then
\begin{align*}
  \lVert f_\theta(u, \Delta t, \mathbf{z}) - f_\theta(u, 0, \mathbf{z}) \rVert
  &\leq L \, |\Delta t| , \\
  \lVert \Delta t \cdot f_\theta(u, \Delta t, \mathbf{z}) \rVert
  &\leq |\Delta t| \bigl( \lVert f_\theta(u, 0, \mathbf{z}) \rVert
     + L \, |\Delta t| \bigr) \;\xrightarrow{\;\Delta t \to 0\;}\; 0 .
\end{align*}
The operators used here consist of linear layers,
Lipschitz-continuous activations and normalisation layers with a positive
stabilising constant, so the assumption holds. The constant $L$ is not
controlled during training and can be large; on the mask channel the
operator in fact learns to scale its output with $1/\Delta t$ within the
observed intervals (\S\ref{sec:experiments:ablations:time}). The statement
therefore concerns only the limit and says nothing about how quickly it is
approached. The
leading $u_t$ term is also a deliberate prior: consecutive visits are
almost identical, because GA progresses little over a typical interval
between visits. Passing the current state through unchanged relieves the
network of reproducing the whole state. It only has to model the change
over the interval.

The output of $f_\theta$ is signed and unbounded, so the model can in
principle also predict a shrinking lesion. Atrophic tissue does not
regenerate, and a shrinking lesion is not clinically plausible. A
constraint that prevents the lesion from shrinking is nevertheless not
imposed, because the reference
segmentations themselves shrink locally between most pairs of visits
(\S\ref{sec:discussion:limitations}). The persistence prior therefore rests
on slow change alone.

The final layer of every operator's output head is initialised to zero,
weights and bias alike. Before training, $f_\theta$ therefore outputs zero
for every input, and Equation~\eqref{eq:method:residual-update} reduces to
exact persistence. Every arm starts from the same function.

Equation~\eqref{eq:method:residual-update} has the form of one explicit
Euler step (\S\ref{sec:background:pde-solvers:time}) whose step size
differs from window to window. The Euler form does not, however, make $f_\theta$ a
time derivative: a network trained with this update need not be a
consistent discretisation of any continuous-time system \citep{Ott2021}.
Whether such a reading holds is tested
in~\S\ref{sec:experiments:validity:swap}.

\subsection{Multi-Channel State Propagation}
\label{sec:method:multichannel}

% Supervisor review 2, SV-4.4 (2026-10-17): "(C, N, K) = (11, 50176, 1)

% the last visit index in Section 2.5.2.
The full eleven-channel state of~\S\ref{sec:data:state} is carried through
every component of the framework; this subsection describes only how the
channels are laid out as tensors. The state
$u_k \in \mathbb{R}^{C \times H \times W}$ of~\S\ref{sec:background:problem}
is stored per window as a matrix of $N = H \cdot W = 50\,176$ grid nodes by
$C = 11$ channels, with the nodes ordered row-major over the
$49 \times 1024$ grid. At run time, a batch of $B$ windows is stacked into
a node-feature matrix of shape $(B \cdot N,\, C)$. Operators that work on
the image grid (\S\ref{sec:method:family:dense}) use the layout
$(B, C, H, W)$ instead.

All eleven channels are both input and output of the operator. The mask
channel is the clinical target, and the ten layer channels are auxiliary
targets. Each output channel receives its own independent prediction. The
loss weights the mask channel more heavily than the layer channels, with
the weights set in~\S\ref{sec:method:training}.

\subsection{Conditioning: Patient Covariates}
\label{sec:method:covariates}

Every window carries two patient-level covariates, the age of the patient
at the start visit and the sex. Their extraction and encoding are described
in~\S\ref{sec:data:covariates}. Both covariates are global quantities: a
visit has one value of each, and that value is shared by all $50\,176$
grid positions. Along the trajectory of one eye, the sex is constant and
the age advances only with the elapsed time. Because the covariates carry
no spatial information, they act on the prediction of an operator only as
a whole and cannot point to a location on the grid or shape the lesion
boundary locally.

The covariates are included because age and sex are plausible modulators
of how fast GA progresses. They are enabled in the canonical configuration
of every operator. Each operator receives them together with $\Delta t$;
how they enter its forward pass is described with the operator
in~\S\ref{sec:method:family}.

\subsection{Objective}
\label{sec:method:training:loss}
\label{sec:method:training}

The loss is computed on the normalised state (\S\ref{sec:data:normalization})
and has two terms, a channel-weighted mean squared error (MSE) and a
soft-Dice term on the mask channel:
\begin{equation}
  \mathcal{L} \;=\; \frac{1}{\bar{w}} \sum_{c=0}^{10} w_c\,
  \mathcal{L}_{\text{MSE}}^{(c)} \;+\; \lambda_{\text{Dice}}\,
  \mathcal{L}_{\text{Dice}},
  \label{eq:method:loss}
\end{equation}
where $\mathcal{L}_{\text{MSE}}^{(c)}$ is the mean squared error of
channel~$c$, $w_c$ its weight and $\bar{w}$ the mean of the weights.
The mask channel ($c = 0$), which is the clinical target, has the weight
$w_0 = 5$, and each of the ten layer channels has the weight $w_c = 1$.
Dividing by the mean weight keeps the scale of the term comparable to an
unweighted MSE. The layer channels are auxiliary targets, but the operator
must still predict them, because they are part of the next state that is
fed back during a rollout. The same loss is used in training and in
validation.

The second term is a soft-Dice loss on the mask channel
\citep{Milletari2016}, with the weight $\lambda_{\text{Dice}} = 5$. It
counters an imbalance in the data: between two consecutive visits, almost
all mask pixels are unchanged, so a plain MSE is dominated by static pixels
and gives little gradient at the moving lesion boundary. A model trained
on it can learn to copy its input. The soft-Dice term restores gradient in
the band around the binarisation threshold, which is where the boundary
lies. Unlike the original soft-Dice loss, which scores a segmentation
probability map, the term is applied here to a regression output. The prediction $p$ of the mask channel is first
turned into a soft mask,
\begin{equation}
  p_{\text{soft}} \;=\; \sigma\!\left(s\,(p - \tau)\right),
  \label{eq:method:soft-mask}
\end{equation}
where $\sigma$ is the logistic sigmoid, $s = 2$ the sharpness and $\tau$
the physical threshold of 0.5 mapped into normalised space. The evaluation
uses the same mapping (\S\ref{sec:data:normalization}), so the loss and the
metric agree on where the threshold lies. With the hard-thresholded target
mask $t$, the term is
$\mathcal{L}_{\text{Dice}} = 1 - 2 \sum p_{\text{soft}} t \,/\,
(\sum p_{\text{soft}} + \sum t)$.

The soft-Dice term is computed per eye and then averaged over the batch.
A Dice score is a ratio of sums. If the sums were pooled over the whole
batch, the gradient for one eye would depend on which other eyes it was
batched with. Scoring per eye also matches the evaluation, which scores
each eye separately before averaging.

The soft-Dice term has one accepted side effect. Because the sigmoid of
Equation~\eqref{eq:method:soft-mask} does not saturate at the physical mask
values, the term stretches the raw mask predictions away from the
threshold. This cannot change a thresholded prediction, but it changes
the raw error of the mask channel. It is one reason why the evaluation does
not compare operators on raw errors (Chapter~\ref{ch:experiments}).

\subsection{Time-Budgeted Pushforward Curriculum}
\label{sec:method:training:curriculum}

The operators are trained with the pushforward trick of
\citet{Brandstetter2022} (\S\ref{sec:background:neural-pde}): the model is
rolled forward on its own predictions without gradients, and only the
final step is supervised. The original counts the depth of this rollout in
steps. With irregular visit intervals (\S\ref{sec:data:temporal}), a step
count is not a comparable quantity: two steps can mean 180 days for one eye
and 720 days for another. The framework therefore counts the depth in
elapsed days.

Training proceeds in passes; in each pass, every training eye contributes
one randomly chosen start window. Each training pass draws a time budget
$B$ uniformly from $\{0, 1, \dots, \min(e, U)\} \times 180$ days, where $e$
is the current epoch and $U$ the largest number of 180-day units in a
budget. The base of 180 days is the modal visit interval of the cohort
(\S\ref{sec:data:temporal}). Every reported run uses $U = 2$, so the
largest budget is 360 days, which matches the one-year evaluation anchor.
Because the upper limit is $\min(e, U)$, the largest budget grows by 180
days per epoch over the first $U$ epochs; after that, budgets of 0, 180 and
360 days are drawn with equal probability. A budget of zero gives a plain one-step pass on observed
inputs.

For a given budget, only start windows that can realise it are sampled.
The chain of consecutive visits from such a window must reach at least $B$
days in total, and its first interval must not exceed $B$. If an eye has no
such window, sampling for that eye falls back to all of its windows.
% Checked 2026-10-01 in utils/utils.py (_rebuild_valid_t0s): the restriction
% applies only for B > 0; at B = 0 any window is drawn.
The number of unrolled steps for each eye then follows an undershoot rule:
it is the largest $n$ for which the $n$ rolled intervals and the final,
supervised interval together stay within $B$. The chain never overshoots
the budget, so eyes on different visit schedules are trained to the same
elapsed horizon. The undershoot rule is also the reason for the 180-day
base: a budget of 90 days, the shortest interval, can never chain two
visits (\S\ref{sec:data:temporal}), so the curriculum would not unroll.

Within a batch, the eyes are grouped by their number of unrolled steps.
Each group is rolled forward $n$ steps without gradients: at every step,
the next window of the eye is fetched and its input state is replaced by
the model's own prediction. All channels are rolled, including the
predicted mask. An eye whose sequence ends is dropped from the chain. The
group then receives one forward pass with gradients, and the loss is taken
against the observed next state. The group losses are combined, each
weighted by the share of the batch its group holds.

\subsection{Optimisation}
\label{sec:method:training:optim}

Table~\ref{tab:method:hparams} lists the training settings that every
operator shares; this subsection explains the optimiser and the
schedule. All operators are trained with AdamW \citep{Loshchilov2019}, a
learning rate of $2 \times 10^{-3}$ and a weight decay of
$1 \times 10^{-2}$ on all trainable parameters. The learning rate is
multiplied by 0.4 at the start of epoch 5 and again at the start of epoch
20, counting from 0, so the first five epochs run at the initial rate.

Training runs for 30 epochs of 20 passes each, with a batch size of four
eyes. Because the number of training eyes differs between the folds
(\S\ref{sec:data:splits}), an epoch has between 280 and 320 optimiser
steps, depending on the fold.

Gradients are clipped to a norm of 1.0 separately for each trainable
module, so that a large gradient in one module cannot shrink the updates of
another. For the
single-network operators of the main comparison, this amounts to one clip
over the whole model. The separation matters for the moving-mesh extension
of Appendix~\ref{app:mm-pde}.

Unless stated otherwise, every reported run uses seed 42; replication runs
with seed 7 are reported in Chapter~\ref{ch:experiments} and
Appendix~\ref{app:ablations}. The model is validated on the held-out
fold after every epoch (\S\ref{sec:data:splits});
\S\ref{sec:experiments:protocol:late} sets out which epochs enter the
reported numbers and why.

\section{The Operators}
\label{sec:method:family}

This section describes the operators placed in the slot
of~\S\ref{sec:method:framework}. Each was chosen to isolate one property:
the reach of the spatial context of one step (the message-passing graph
neural network on two different graphs,
\S\ref{sec:method:mppde}--\S\ref{sec:method:graph}), the amount of spatial
context needed (two truncated versions of it,
\S\ref{sec:method:family:floors}), multiscale local detail (the U-Net,
\S\ref{sec:method:family:dense}), global spectral support without and with
a local path (the Fourier Neural Operator and a hybrid,
\S\ref{sec:method:family:dense}), an explicit transport term (the Finite
Element Network, \S\ref{sec:method:family:fen}) and the order of time
integration (a Runge--Kutta wrapper around any of these operators,
\S\ref{sec:method:family:rk}). The interface shared by all operators is
stated first (\S\ref{sec:method:family:contract}), and the parameter
matching last (\S\ref{sec:method:family:params}).

\subsection{The Operator Contract}
\label{sec:method:family:contract}

Every operator satisfies the same interface: it is built from the same
metadata (one time step, eleven state channels and two covariates) and
consumes the same batch. It returns the full next state in the residual
form of Equation~\eqref{eq:method:residual-update}, and its final layer is
initialised to zero (\S\ref{sec:method:dt-residual}), so that every
operator starts training at exact persistence. The residual and the next
state are computed from one shared internal computation, so the two cannot
become inconsistent; the integration wrapper
of~\S\ref{sec:method:family:rk} integrates this same residual.

No operator uses a normalisation that keeps batch statistics. The training
curriculum of~\S\ref{sec:method:training:curriculum} rolls the model forward on its
own predictions, without gradients but in training mode, so the states it
produces drift away from the observed ones. Batch
normalisation \citep{Ioffe2015} would normalise these drifted states with
the statistics of the current batch and so remove the perturbation the
curriculum is meant to expose the model to. It would also
write the drifted statistics into the running estimates that evaluation
later uses, so that training and evaluation would behave as two different
operators.

The operators that work on the image grid (the U-Net, the Fourier Neural
Operator and its local-kernel hybrid) receive identical inputs, so that a
difference between them cannot come from the information they receive.
Each takes sixteen input channels: the eleven state channels, $\Delta t$
broadcast as a constant plane, the two covariates broadcast as constant
planes, and two coordinate ramps running from zero to one along each axis,
following the CoordConv construction of \citet{Liu2018}.

\subsection{Message-Passing Graph Neural Network}
\label{sec:method:mppde}

The graph operator is the message-passing neural PDE solver (MP-PDE) of
\citet{Brandstetter2022}, the learned-stencil solver introduced
in~\S\ref{sec:background:pde-solvers:neural}. It builds on the graph
neural network model of \citet{Scarselli2009} and the message-passing
formulation of \citet{Gilmer2017}. Several of its design decisions also
became part of the shared framework: the time handling, the output layer
and the one-step prediction. The original is summarised first, followed by
the modifications proposed in this work and a summary of them.

% Sections 4.3.3 and 4.3.5 removed; headings renamed as he suggested.

\paragraph{The original MP-PDE.}
MP-PDE is an autoregressive neural solver for time-dependent PDEs. It
operates on a spatial graph, built on the analogy that grid points or
finite-volume cells become nodes and numerical stencils become edges. The
graph is built from a cut-off radius on regular grids, or by connecting
the $k$ nearest neighbours on irregular meshes.

The architecture follows the encode--process--decode pattern
\citep{Battaglia2018, SanchezGonzalez2020}. An encoder, a per-node
two-layer multilayer perceptron (MLP), lifts the node features into a
latent space. It computes
$f_i^0 = \epsilon([u_i^{k-K:k}, x_i, t_k, \theta_{\text{PDE}}])$ from the
last $K$ states of the node, its position, the current time and the
equation features.

The processor applies several rounds of message passing to the latent
node states (six in the original paper). The message function is
$m_{ij}^m = \phi(f_i^m, f_j^m, u_i^{k-K:k} - u_j^{k-K:k}, x_i - x_j,
\theta_{\text{PDE}})$, and the node update is
$f_i^{m+1} = \psi(f_i^m, \sum_j m_{ij}^m, \theta_{\text{PDE}})$. Both
$\phi$ and $\psi$ are two-layer MLPs with skip connections and
normalisation layers. The relative position $x_i - x_j$ builds
translational symmetry into the network. The solution difference
$u_i - u_j$ lets each message act as a learned local difference operator,
that is, a learned stencil.

The equation feature vector $\theta_{\text{PDE}}$ holds the PDE
coefficients and the boundary-condition identifiers. It is injected at the
encoder and at every message-passing layer. Injecting it at every layer
allows a single trained solver to generalise across a family of equations,
and removing it degrades performance most when the equation parameters
vary across the dataset.

The decoder is a shallow one-dimensional convolutional network with
weights shared across space. It treats the final hidden vector of each
node as a temporal signal and convolves along it, producing one update per
bundled step, $d_i = (d_i^1, \dots, d_i^K)$. The residual update
$u_i^{k+l} = u_i^k + (t_{k+l} - t_k)\, d_i^l$ gives the prediction for each
substep $1 \leq l \leq K$. As the step size approaches zero, the prediction
approaches the current state, which keeps the update consistent
(\S\ref{sec:background:pde-solvers:time}). The model is trained with
temporal bundling and the pushforward trick
(\S\ref{sec:background:neural-pde}). The original models have roughly one
million parameters and a hidden size of the order of 128, and they are
trained with AdamW.

The original paper names two limitations: it needs high-quality
numerical ground truth for training, and it has no formal accuracy
guarantees. A further one, not named by its authors, is that a uniform mesh
is wasteful in smooth regions and under-resolved at sharp gradients; it
motivates the moving-mesh extension of \citet{Hu2024}
(Appendix~\ref{app:mm-pde}).

\paragraph{Proposed modifications.}
The forward pass consists of an encoder, a number of message-passing
rounds and a decoder. The notation follows the summary above.
Each node $i$ carries the normalised eleven-channel state $u_i$ and its
physical position $(x_i, y_i)$ in millimetres. The positions enter the
network divided by the domain size, as $(x_i / L_x,\, y_i / L_y)$.

Each node also receives a conditioning vector $\mathbf{c}_i$. In the
canonical configuration it has three entries: the interval $\Delta t$ in
years, the z-scored age and the sex of the patient. All three are
graph-level quantities, broadcast to every node of the graph. The
conditioning vector takes the place of the equation feature vector
$\theta_{\text{PDE}}$ of the original: no governing equation or
coefficients are known for GA, so the interval and the covariates are used
instead. As in the original, the
vector is injected at three points: the encoder input, every message and
every node update.

The encoder maps the concatenated node input to a hidden vector,
\begin{equation}
  f_i^{0} \;=\; \epsilon\!\left(\left[u_i,\; x_i / L_x,\; y_i / L_y,\;
  \mathbf{c}_i\right]\right),
  \label{eq:method:encoder}
\end{equation}
where $\epsilon$ consists of a linear layer, layer normalisation, a ReLU
activation, a second linear layer and a final layer normalisation, with no
activation after it.

Each message-passing round $m$ computes a message along every edge from
node $j$ to node $i$ and then updates node $i$:
\begin{align}
  m_{ij}^{m} &\;=\; \phi\!\left(f_i^{m},\; f_j^{m},\; u_i - u_j,\;
    \Delta\mathbf{p}_{ij},\; \mathbf{c}_i\right),
  \label{eq:method:message}\\
  f_i^{m+1} &\;=\; \mathrm{LN}\!\left(f_i^{m} + \psi\!\left(f_i^{m},\;
    \frac{1}{|\mathcal{N}(i)|}\sum_{j \in \mathcal{N}(i)} m_{ij}^{m},\;
    \mathbf{c}_i\right)\right).
  \label{eq:method:update}
\end{align}
Here $\Delta\mathbf{p}_{ij}$ is the offset between the normalised positions
of the two nodes, $\mathcal{N}(i)$ is the set of neighbours of node $i$, and
$\mathrm{LN}$ denotes layer normalisation. The message function $\phi$ and
the update function $\psi$ each consist of two linear layers, each followed
by a ReLU activation. As in the original, the state difference $u_i - u_j$
lets the message act as a learned local difference operator. Every round
receives the state $u_i$, the positions and the conditioning vector again,
so this information is available at every depth. Each update ends in a
residual connection followed by a normalisation layer; the original also
uses skip connections in its message-passing layers, and only the type of
normalisation differs. The canonical configuration aggregates messages by
their mean, as written in Equation~\eqref{eq:method:update}, and uses two
message-passing rounds and a hidden width of 64; larger and smaller
settings are compared in~\S\ref{sec:experiments:ablations:capacity}.

All normalisation layers are per-node layer normalisations
\citep{Ba2016}. Each node is normalised over its own feature vector, so the
operator keeps no batch statistics, as the contract
of~\S\ref{sec:method:family:contract} requires.

Because the framework predicts one step ($K = 1$,
\S\ref{sec:method:framework}), the one-dimensional convolutional head of
the original, which exists to emit the $K$ bundled steps, was replaced by
an MLP decoder. It maps the final hidden vector $f_i^{M}$ to the eleven
channels: a linear layer, layer normalisation and a ReLU, applied twice,
followed by a final linear layer whose full-rank output gives every channel
its own independent prediction. The final layer has no normalisation or
activation, because the output is a signed and unbounded residual, and it
is initialised to zero, which yields the persistence start
of~\S\ref{sec:method:dt-residual}. The predicted next state of node $i$ is
then $u_i + \Delta t \cdot \delta(f_i^{M})$, where $\delta$ denotes the
decoder; this is Equation~\eqref{eq:method:residual-update} at node level.

\subsection{Graph Construction on an Anisotropic Grid}
\label{sec:method:graph}

% Supervisor review 2 (2026-10-17): SV-4.7 (name the distance; he reads the
% index-space graph as geodesic), SV-4.8 (prior use of dilated
% neighbourhoods, Yu2016, Li2019), X4 (micrometres); AI 4b.1-4b.8.
The graph determines which nodes exchange messages, and therefore how far
information travels in one round. The modelling grid has 49 rows and 1024
columns, or 50\,176 nodes. Rows are 121.18\,\textmu{}m apart, while
columns are only 5.68\,\textmu{}m apart (\S\ref{sec:data:spatial}). Along a
row, the nodes are therefore about 21 times denser than across rows. The
node positions are stored in physical millimetres.

The usual construction on irregular meshes, a $k$-nearest-neighbour graph,
connects each node to the $k$ nodes at the smallest Euclidean distance
between their physical positions (Figure~\ref{fig:method:stencils}a). On
this grid it does not connect the rows: the twelve physically nearest
neighbours of every node all lie in its own row, and no edge crosses rows.
Message passing on such a graph runs along rows only, no information can
cross from one row to the next at any network depth, and the grid
decomposes into 49 independent one-dimensional rows. This construction is
therefore not used in any reported experiment; it is described because it
is the natural first choice and shows that the anisotropy of the grid has
to be taken into account.

Measuring the Euclidean distance between integer grid indices (row,
column) instead restores two-dimensional connectivity
(Figure~\ref{fig:method:stencils}b). With $k = 12$ and without
self-loops, the neighbourhood of an interior node is exactly the set of
nodes at squared index distance at most four. On the integer grid this set
coincides with the ball of radius two in geodesic (hop) distance on the
4-connected lattice, a diamond: the four direct neighbours, the four
diagonal neighbours and the four neighbours two steps away along either
axis. The resulting graph has
602\,112 directed edges; about 33\,\% connect nodes in the same row,
50\,\% nodes one row apart and 17\,\% nodes two rows apart. About 8.5\,\%
of the nodes (4\,276), on and next to the border of the grid, do not have
the full interior neighbourhood.

This index-space graph is the graph of the $k$-nearest-neighbour arm in
Chapter~\ref{ch:experiments}. It restores two-dimensional connectivity,
but its physical reach differs strongly between the two axes. A
neighbourhood that is symmetric in grid steps inherits the 21:1 anisotropy
of the grid. One hop reaches about $\pm 242$\,\textmu{}m across rows but
only about $\pm 11$\,\textmu{}m along a row. After the two message-passing
rounds of the canonical configuration, a node has received information
from at most four columns away, about $\pm 23$\,\textmu{}m along the row.

For comparison, the GA front advances a median of about 12 columns
(68\,\textmu{}m) between two visits 180 days apart; the upper quartile is
17 columns (97\,\textmu{}m) and the 90th percentile 23 columns
(131\,\textmu{}m). A single hop along a row therefore covers only a small
fraction of the distance the front typically moves between two visits, and
the four columns reached after two rounds are about a third of the median
advance. The index-space graph restores connectivity but not reach, which
motivates a second graph construction whose reach along a row matches the
scale of the lesion change.

The dilated stencil is designed to close this gap
(Figure~\ref{fig:method:stencils}c). Each interior node is connected to the
nodes at row offsets $\{-1, 0, +1\}$ and column offsets
$\{0, \pm 7, \pm 14, \pm 21\}$, excluding the node itself: 20 neighbours in
total. It follows the idea of dilated convolutions \citep{Yu2016}, which
apply the same kernel at a larger range by spacing its taps apart, so that
the receptive field grows while the number of parameters stays the same;
here the dilation is seven along rows and one across rows. Dilated
neighbourhoods have also been used in graph networks \citep{Li2019}, where
the $k$ neighbours are taken from the $k \cdot d$ nearest ones by skipping
every $d$-th, measured in the feature space of the current layer. Here the
dilation is instead set in physical distance, because what one hop has to
cover is the physical advance of the front between two visits; an
isotropic dilation in grid steps would keep the 21:1 imbalance of the
index-space graph. One hop reaches $\pm 121$\,\textmu{}m across rows and
$\pm 119$\,\textmu{}m along a row, nearly equal on both axes at about
120\,\textmu{}m per hop. Along a row, one hop spans 21 columns, close to the
90th percentile of the per-visit front advance. The design thus derives the
reach from the physical scale of the lesion. The dilated stencil changes
only the edge set; the network architecture and every other component are
the same as on the index-space graph, and the stencil adds no parameters.
Chapter~\ref{ch:experiments} tests this choice against smaller and larger
reaches.

\subsection{Dense Operators: U-Net, FNO and a Local-Kernel Hybrid}
\label{sec:method:family:dense}

The three operators of this subsection are dense grid operators: they act
on the state as an image on the full $49 \times 1024$ grid and receive
sixteen input channels: the eleven state channels, $\Delta t$, the two
covariates and two coordinate ramps (\S\ref{sec:method:family:contract}). The first
dense operator is a U-Net \citep{Ronneberger2015}. The
original was designed for biomedical image segmentation. It consists of a
contracting and an expansive path. Each contracting step applies two
unpadded $3 \times 3$ convolutions, each followed by a ReLU, and then a
$2 \times 2$ max pooling with stride two; the number of feature channels
doubles at each downsampling step. Each expansive step upsamples, halves the
channels with an up-convolution, concatenates the correspondingly cropped
feature map from the contracting path, and applies two further $3 \times 3$
convolutions. A final $1 \times 1$ convolution maps to the output classes.
\citet{Gupta2023} study modernised U-Nets as PDE surrogates and
describe them as handling local and global information through
the down- and up-sampling paths.
In the GA domain, \citet{Salvi2025} predict future lesion growth with a
two-dimensional U-Net on fundus autofluorescence images.

The U-Net used here departs from the original in four ways. First, each
convolution is followed by group normalisation with a single group before
the ReLU; the original uses no normalisation.
With one group, group normalisation normalises each sample over all its
channels and positions and keeps no batch statistics \citep{Wu2018}. Second, pooling
is anisotropic. The factors (rows, columns) are $(1, 2)$, $(1, 2)$,
$(2, 2)$ and $(2, 2)$, so the grid shrinks from $49 \times 1024$ through
$49 \times 512$, $49 \times 256$ and $24 \times 128$ to $12 \times 64$. Rows
are downsampled by a factor of four in total and columns by a factor of
sixteen, which reduces the 21:1 ratio of row to column spacing to about
5:1 without removing it. The schedule was deliberately not tuned further:
a comparison model whose geometry had been optimised on this dataset would
make a weaker control. Third, upsampling is nearest-neighbour instead of an
up-convolution, and the output has the grid size of the input. Fourth, the
final $1 \times 1$ layer is zero-initialised and returns a residual rather
than class scores. A base width of five, that is, five channels at the
input stage, gives 83\,081 parameters.

The second dense operator is the Fourier Neural Operator (FNO) of \citet{Li2021}. The input is first lifted to a wider representation by a local
map. Each layer then combines a local linear transform with a non-local
integral operator and applies a nonlinearity. The integral operator
transforms its input to Fourier space, multiplies the retained low modes by
learned complex weights, and transforms back. Modes above a threshold are
truncated; both the low positive and the low negative frequencies are kept.
A local projection maps the result to the output. The paper shows that the
Fourier layers are invariant to the discretisation, and that truncation does
not limit the output to the retained modes, because the nonlinearities and
the projection recover higher frequencies. For its two-dimensional problems,
the original uses four Fourier layers, ReLU activations with batch
normalisation, 12 modes per dimension and a width of 32. It notes that the
local linear term helps the model handle non-periodic boundaries.

The FNO used here keeps four blocks, each a spectral convolution plus a
pointwise $1 \times 1$ path, and departs from the original in the
following respects. It uses GELU activations between blocks instead of ReLU,
and no normalisation. It retains 14 modes per axis instead of 12, and its
width is 5 instead of 32, which gives 79\,160 parameters. The output passes
through a $1 \times 1$ convolution to 32 channels, a GELU and a
zero-initialised $1 \times 1$ projection. Because the domain here is a crop
and not a periodic physical domain (\S\ref{sec:data:spatial}), the field is
zero-padded by about one eighth per axis before the transform, from
$49 \times 1024$ to $56 \times 1152$, and cropped back after the spectral
blocks; the original does not pad and relies on the local linear term
instead. The equal mode count on both axes follows from the geometry: the
physical domain is nearly square ($5.94 \times 5.82$\,mm), so equal mode
counts give nearly equal physical bandwidth on both axes, a property the
index-space graph of~\S\ref{sec:method:graph} does not have. Dividing the
padded extent by the highest retained mode index, 13, gives a finest
retained wavelength of about 520\,\textmu{}m across rows and
500\,\textmu{}m along columns. The mode count was not ablated.

The third dense operator is a local-kernel hybrid.
\citet{LiuSchiaffini2024} observe that global operations in Fourier
space are prone to over-smoothing and may miss local details. They add
localised operators in parallel to the Fourier layers and the pointwise
path. Their differential kernels subtract the kernel mean and rescale by the
reciprocal grid width, so that the convolution converges to a differential
operator as the grid is refined; their localised integral kernels use
discrete-continuous convolutions. The hybrid used here is the simplest
instance of this idea. It widens the pointwise $1 \times 1$ path of each FNO
block to an unconstrained $3 \times 3$ convolution, so a local path runs in
parallel with the spectral one. Unlike the original, it operates at a single
training resolution and uses no mean subtraction, rescaling or
discrete-continuous convolutions, so it is not the resolution-consistent
operator of that paper. The spectral path keeps
global support and the local path gains one ring of neighbours, at a cost
of 800 parameters (79\,960 in total). With a kernel size of one, the model
reduces exactly to the plain FNO.

\subsection{The Finite Element Network}
\label{sec:method:family:fen}

The Finite Element Network (FEN) of \citet{Lienen2022} builds the
update from a finite-element discretisation of an unknown PDE. Its
architecture defines the output as a time derivative instead of a next
state; it is the only operator in the survey that does so. Whether the
trained model behaves as a valid continuous-time system is a separate
question, tested in Chapter~\ref{ch:experiments}.

The original uses a Galerkin method with the P1 basis of piecewise-linear
hat functions, by default on a Delaunay triangulation of the observation
points. The resulting system involves the mass matrix of inner products
between basis functions, which is lumped by row-wise summation, a
standard approximation for time-dependent problems that makes its inversion
trivial. The inner products are factored so that a network predicts one
coefficient per cell, vertex and feature from the time, the cell centre,
the local vertex coordinates and the vertex features; this network is the
free-form term. The
transport variant, T-FEN, adds a convection term. It starts from the
conservative form $-\nabla \cdot (v u)$, applies the product rule and
assumes a divergence-free velocity, which leaves the advective form
$-v \cdot \nabla u$. A second network predicts one velocity per cell and
feature; since the velocity is constant within each cell, it is
divergence-free there, but not across cells. Both networks are tanh MLPs,
and the resulting ODE is solved with the adaptive Dormand--Prince solver
(dopri5).

The FEN used here triangulates the regular grid by splitting every grid
cell into two right triangles, which gives 98\,208 triangles over the
50\,176 nodes; each node belongs to one, two, three or six triangles. The
mass matrix is lumped as in the original. On this equal-area lattice, the
lumped assembly is exactly a mean over the triangles adjacent to a node.
The FEN is therefore a message-passing network with mean aggregation over
triangles, each linking three nodes, and its finite-element formulation
differs from such a network only at the boundary. The free-form term is a tanh MLP
of depth four and width 96, without normalisation and with a
zero-initialised head. It receives the three vertex states of a triangle, a
triangle-type indicator for the two triangle orientations, the covariates
and optionally the normalised triangle centre, and it outputs one
coefficient per vertex and channel.

The transport term is a second MLP that predicts one velocity per triangle
and channel, in millimetres per year. The assembled operator is the
advective form $-v \cdot \nabla u$ with a velocity that is constant within
each triangle, as in the original. As in the original, the velocity is not
divergence-free across triangles, so reading it as a physical advection
speed rests on an assumption that the model does not enforce globally. The gradient coefficients are assembled in grid
units, so the 21:1 axis imbalance never reaches the MLPs; only the velocity
conversion uses millimetres. The transport term runs on its own coarser mesh,
made of seven interleaved triangulations, each of which connects every
seventh column (97\,632 triangles in total), while the free-form term
uses the full-resolution mesh. This coarser mesh is the finite-element
counterpart of the dilated stencil of~\S\ref{sec:method:graph}.

The implementation departs from the original in the following points. A
regular lattice replaces the Delaunay triangulation. A triangle-type
indicator replaces the local vertex coordinates, which on this lattice take
only two forms. The covariates are added as inputs. The time is not an
input, so the learned time derivative has no explicit dependence on time
(it is autonomous), a variant the original paper explicitly allows. Integration uses a fixed-step scheme instead of the
adaptive dopri5 solver. The advective form and the per-cell velocity are the
same as in the original; the energy-conserving form of the transport
operator described below is a further departure.

One evaluation of the time derivative only couples nodes that share a
triangle, so spatial reach has to come from sub-steps. The FEN is therefore
always run inside the Runge--Kutta wrapper of~\S\ref{sec:method:family:rk},
with classical RK4 and a fixed physical step of 45 days; $\Delta t$ sets
only the integration horizon. RK4 is used because, in the interior of the
lattice, the assembled transport operator has a purely imaginary spectrum:
an explicit Euler step would amplify every mode for any non-zero velocity,
whereas RK4 has a stability interval on the imaginary axis. It remains
stable only while the velocity times the step, the Courant number in the
sense of the stability condition of~\citet{Courant1928}, stays below a limit
of about 2.4 for this stencil.

The assembled transport operator was trained in two forms. The first is
the Galerkin form described above, as in the original. At a constant
velocity and away from the edge of the domain, it conserves a discrete
energy of the state, the mass-weighted sum of squares $u^\top M u$, as
expected of pure transport, which moves content without creating it. At
the edge of the crop, or where the velocity varies from triangle to
triangle, it does not conserve this energy. No flux term is assembled at
the boundary, so transported content accumulates there, and the operator
has modes that grow instead of travelling. The second form removes this
defect. It keeps only the part of the Galerkin operator $L$ that is
skew-adjoint with respect to the mass matrix $M$, which is its
energy-conserving part,
\begin{equation}
  L_{\text{skew}} \;=\; \tfrac{1}{2}\left(L - M^{-1} L^\top M\right),
  \label{eq:method:fen-skew}
\end{equation}
which conserves $u^\top M u$ for any per-triangle velocity, including at
the edge, where it acts as a closed wall. In the interior and at a constant
velocity, the two forms coincide. The energy-conserving form adds no
parameters and no measurable cost. Figure~\ref{fig:method:fen-toy} shows
the difference between the two forms on a small grid.

\subsection{Fixed-Step Runge--Kutta Integration}
\label{sec:method:family:rk}

% Supervisor review 2, SV-4.9/SV-4.10 (2026-10-18): restructured without
% run-in headings (uses first, then Euler/RK4, then why the field is made
% autonomous, then jump vs continuous time); results no longer previewed
% (AI 4b.43, S8). Rewritten 2026-10-01 at the author's request before that.
The Runge--Kutta wrapper is placed around an operator and changes only how
the operator's output is turned into the next state; it adds no
parameters. It has three uses. First, the finite-element network outputs
a time derivative and needs an integrator (\S\ref{sec:method:family:fen}).
Second, it allows the integration order to be varied on its own: the same
operator is trained with one Euler step and with RK4
(\S\ref{sec:experiments:ablations:time}). Third, it makes it possible to
test whether a trained model describes a continuous process
(\S\ref{sec:experiments:validity:swap}).

The canonical update of Equation~\eqref{eq:method:residual-update} is one
explicit Euler step: the operator is evaluated once, at the current state,
and its output is applied over the whole interval $\Delta t$. A Runge--Kutta
scheme evaluates the operator several times within the interval, at
intermediate states, and combines the results. The classical fourth-order
scheme (RK4) \citep{Runge1895,Kutta1901} evaluates the operator four times
per step and takes a weighted average \citep{Butcher1987, Hairer1993};
every reported model trained with the wrapper uses it. The interval can
also be split into several sub-steps, each of which is one RK4 step. The
sub-step length is set separately for each eye in a batch, either as
$h = \Delta t / n$ or from a physical step length in days, with the number
of sub-steps rounded up from the ratio of the interval to that length. An
eye is therefore integrated with the same steps whether it is batched with
others or evaluated alone; eyes with shorter intervals take zero-length
steps until the longest interval in the batch is complete. As a check of
the implementation, the observed convergence orders on the test problem
$\mathrm{d}u / \mathrm{d}t = -\lambda u$ are 0.99, 2.04, 2.04 and 4.35 for
the Euler, midpoint, Heun and RK4 schemes, close to their nominal orders of
one, two, two and four.

Because RK4 evaluates the operator at intermediate states within the
interval, the operator should describe the rate of change at a state, not
the change over the full interval. Inside the wrapper, the $\Delta t$ entry
of the operator's conditioning vector is therefore set to zero, so the
operator receives no information about the length of the interval. Its
output is then a rate of change at the current state with no explicit
dependence on time, an \emph{autonomous} field, and the integrator alone
determines over which interval this rate is applied; the state still
changes by the integrated rate. In this reading the wrapped model is a
Neural ODE in the sense of \citet{Chen2018}. Positions, graph edges and
covariates stay fixed across the stages of one step. The wrapper requires
the $\Delta t$-multiplied residual form of
Equation~\eqref{eq:method:residual-update}, because without the
multiplication by $\Delta t$ the operator's output is not a rate and cannot
be integrated.

The canonical model is trained as a single jump: it learns which state
follows after an interval of length $\Delta t$, in one step. Training does
not require two jumps of length $\Delta t / 2$ to lead to the same state as
one jump of length $\Delta t$. In a continuous-time model, by contrast,
splitting the interval into more or finer steps must not change the
prediction. \citet{Ott2021} show that a model trained with an overly coarse
step can reach high accuracy and still lose this property. They test it by
evaluating the trained model with solvers of equal or smaller
discretisation error and checking whether its predictions stay the same;
\citet{Krishnapriyan2023} make the same point for learned models of
physical systems. Because the wrapper can integrate any trained operator
with other schemes and step counts, it makes this step-size test
possible. Its outcome is reported in~\S\ref{sec:experiments:validity:swap},
and the accuracy of the models trained with the wrapper
in~\S\ref{sec:experiments:ablations:time}.

\subsection{Parameter Matching}
\label{sec:method:family:params}

Every architecture arm is matched in size to the canonical graph solver
of~\S\ref{sec:method:graph}, which has 67\,147 parameters: its width is
chosen to come as close to this count as the width granularity allows, so
that differences between arms cannot be attributed to extra parameters.
Table~\ref{tab:method:params} lists every configuration. A separate
experiment tests whether the size at which the arms are matched affects the
comparison, by scaling every architecture class from about a sixth to
three to four times its size (\S\ref{sec:experiments:ablations:capacity}).

All architecture arms lie within a factor of 1.25 of the reference. The two
floors lie below this band because they are not architecture arms: the
one-hop floor is a rung of the locality ladder

fifth of the parameters, is a control that marks what a model without

33\,718 to the transport head. Why this gap does not explain the

\section{Implementation Details}
\label{sec:method:implementation}

The framework is implemented in Python with PyTorch 2.4.1 and CUDA 12.1
\citep{Paszke2019}. The graph operators use PyTorch Geometric 2.6.1
\citep{Fey2019}.
% Versions read from the cluster container
% pytorch-2.4.1-cu121-cudnn9-runtime.sif on 2026-10-01 (2.4.1+cu121, 2.6.1).
All dependencies are pinned in a fixed container image. Every reported run
was trained on a single NVIDIA RTX A6000 GPU on a cluster managed by
Slurm, and the five folds of an experiment were submitted together as a job
array.

The windows of each fold are precomputed once before training. This step
performs the crop and pad, the normalisation and the extraction of
$\Delta t$ and the covariates, and it builds the index-space neighbour
graph. Because the grid is the same for every visit, one graph serves all
windows. The dilated stencil of the canonical graph network
(\S\ref{sec:method:graph}) is built at run time from the grid indices
rather than stored. All precomputed data are held in memory during
training.

The data loader runs in the main process, because the curriculum changes
the sampling restriction of the dataset at every pass and a change made in
the main process would not reach separate worker processes. All random
number generators (Python, NumPy, PyTorch and CUDA) are seeded, and
deterministic cuDNN algorithms are enforced. Even so, repeated runs of the
same configuration do not give identical results on the GPU.
Chapter~\ref{ch:experiments} quantifies this run-to-run variation and
defines the noise level against which every comparison is read.
