\section{Overview}
\label{sec:method:overview}

This chapter answers the first part of the research question: what kind
of framework the forecast needs. The framework separates the training and
evaluation setup from the spatial operators evaluated inside it. The aim
is to find out which properties a model needs in order to predict GA
progression. Answering
that question requires a controlled comparison. If every candidate
architecture came with its own training pipeline, differences in data
handling, time representation or optimisation would be confounded with
the architectural differences under test. A single pipeline is therefore
fixed, and it provides one swappable slot for the update operator
$f_\theta$. The operator placed in this slot is the only component that
changes between experiments.

Everything outside the slot is held fixed. The input is the eleven-channel
state on the $49 \times 1024$ grid of Chapter~\ref{ch:data}. Time is
handled by a single-step residual update conditioned on the interval
between visits (\S\ref{sec:method:dt-residual}). The loss, the training
curriculum, the optimiser, the epoch budget, the cross-validation folds,
the random seeds, the evaluation and the model selection rule are shared
by every run. A backbone placed in the slot contains architecture only. It
receives the current state and its conditioning inputs in a common batch
format, and it returns the full predicted next state. It may not change the
optimisation loop or carry training settings of its own. A separate
pipeline per architecture would reintroduce exactly the confounds the
design is meant to remove.

The operators run through this pipeline are a message-passing graph
neural network (GNN) on two different neighbourhood graphs
(\S\ref{sec:method:graph}), one of which is the canonical model of this
thesis; a U-Net; a Fourier Neural Operator (FNO); and a hybrid Finite
Element Network (FEN). Several of these are run in more than one variant
(\S\ref{sec:method:family}). A fixed-step Runge--Kutta wrapper can be placed around any
of these operators, and a per-pixel model with no spatial context marks the
lower floor. The arms are parameter-matched to the canonical
configuration's 67\,147 parameters within a narrow band; the matching and
its exceptions are described in~\S\ref{sec:method:family:params}.

\section{The Fixed Framework}
\label{sec:method:framework}

This section defines what every arm shares: the time handling and the
tensor layout of the state. A further shared choice concerns the input
itself. Every operator receives exactly one visit and predicts the state at
the next visit. It sees the current state, the interval to the next visit
and the patient covariates, but no earlier visits. It has no memory of the
trajectory so far.

Two reasons support this design. First, the clinical sequences are short,
with five to thirteen visits per eye (\S\ref{sec:data:dataset}). Using
several past visits as input would leave fewer visits available as
prediction targets. Second, the framework predicts strictly one step at a
time. Some neural PDE solvers, such as MP-PDE, predict several future
steps in one forward pass (temporal bundling,
\S\ref{sec:background:neural-pde}), but not all of the operators compared here
support this. Bundling is therefore removed, so that every operator makes
the same kind of prediction. In addition, as noted above, the sequences
are so short that splitting them into multi-step windows would not be
useful anyway.

curriculum are defined in~\S\ref{sec:method:training}, and the shared

\subsection{\texorpdfstring{$\Delta t$}{Delta t}-Conditioned Residual Formulation}
\label{sec:method:dt-residual}

The original neural PDE solvers use a fixed time step and receive the
absolute time as an input feature. The clinical data offers neither. Visits
occur at irregular intervals, and patients share no common time origin. The
absolute time is therefore replaced by the interval between two
consecutive visits, $\Delta t$, measured in years (\S\ref{sec:data:temporal}).

The transition from the current state $u_t$ to the next state
$u_{t+\Delta t}$ is written as a residual update scaled by the interval:
\begin{equation}
  u_{t+\Delta t} \;=\; u_t \;+\; \Delta t \cdot
  f_\theta\!\left(u_t,\, \Delta t,\, \mathbf{z}\right),
  \label{eq:method:residual-update}
\end{equation}
where $f_\theta$ is the operator in the swappable slot and $\mathbf{z}$
denotes the patient covariates. $\Delta t$ therefore enters twice. It is an
input feature of the network, so the operator can adapt its output to the
length of the interval. It is also the multiplier of the network output.

This form has a useful limit. As $\Delta t$ approaches zero, the predicted
change vanishes and the prediction collapses to $u_{t+\Delta t} = u_t$.
For two visits very close in time, the model thus predicts no change. The
leading $u_t$ term is also a deliberate prior. Consecutive visits are
almost identical, because GA changes slowly relative to the rest of the
retinal state. Passing the current state through unchanged relieves the
network of reproducing the whole state. It only has to model the change
over the interval. The output of $f_\theta$ is signed and unbounded, so the
model can in principle also predict a shrinking lesion, although atrophic
tissue does not regenerate and a shrinking lesion is not clinically
plausible. No monotonic-growth constraint is imposed, because the reference
segmentations themselves shrink locally between most pairs of visits
(\S\ref{sec:discussion:limitations}); the prior rests on slow change alone.

The final layer of every operator's output head is initialised to zero,
weights and bias alike. Before training, $f_\theta$ therefore outputs zero
for every input, and Equation~\eqref{eq:method:residual-update} reduces to
exact persistence. Every arm starts from the same function.

Equation~\eqref{eq:method:residual-update} takes the form of one explicit
Euler step (\S\ref{sec:background:pde-solvers:time}), with a step size that
differs from window to window. It is the same for every operator placed in
the slot. This resemblance to a numerical integrator needs a caution.
The Euler form does not by itself make $f_\theta$ a time derivative or a
rate of change. A network trained with this update need not be a consistent
discretisation of any continuous-time system \citep{Ott2021}. This thesis therefore does not assume such a reading. Instead, it is tested
directly with a solver-swap diagnostic, reported
in~\S\ref{sec:experiments:validity}: a trained model is re-evaluated, without
retraining, under several integration schemes and step counts. A model that
represents a continuous-time system gives nearly the same predictions under
all of them.

\subsection{Multi-Channel State Propagation}
\label{sec:method:multichannel}

The framework carries the full eleven-channel state through every
component. As defined in~\S\ref{sec:data:state}, the state consists of one
binary mask channel and ten layer-boundary depth channels. This subsection
covers only how these channels are laid out and moved as tensors.

Each window stores its input and target state with the layout
$(C, N, K) = (11, 50\,176, 1)$, where $C$ is the number of channels, $N$
the number of grid nodes and $K$ the number of time steps. At run time, a
batch of $B$ graphs is flattened into a node-feature matrix of shape
$(B \cdot N,\; C \cdot K) = (B \cdot 50\,176,\; 11)$. The feature axis is
ordered channel-major and time-minor. The node axis is ordered row-major
over the $49 \times 1024$ grid.

Operators that work on images, such as the convolutional arms
of~\S\ref{sec:method:family}, need the state in the image layout
$(B, C, 49, 1024)$.

All eleven channels are both input and output of the operator. The mask
channel is the clinical target, and the ten layer channels are auxiliary
targets. Each output channel receives its own independent prediction. The
loss weights the mask channel more heavily than the layer channels, with
the weights set in~\S\ref{sec:method:training}.

\section{The Operators}
\label{sec:method:family}

The framework of~\S\ref{sec:method:framework} provides one slot for the
update operator $f_\theta$. This section describes every operator that
occupies it. Each was chosen to isolate one property. A message-passing
graph neural network, run on two different graphs, tests how far the
spatial context of one step has to reach. A U-Net tests multiscale local
detail. A Fourier Neural Operator tests global spectral support without a
local path, and a hybrid adds a minimal local path to it. Two truncated
graph networks test how much spatial context is needed at all. A Finite
Element Network adds an explicit transport term. Finally, a Runge--Kutta
wrapper changes the time integration of any of these operators. Because
all of them run in the same training environment, differences between
them can be attributed to the architecture rather than to the training
protocol.

\S\ref{sec:method:family:contract} states the interface every operator
satisfies. \S\ref{sec:method:mppde} describes the message-passing network
and \S\ref{sec:method:graph} the two graphs it runs on.
\S\ref{sec:method:family:dense} describes the three dense grid operators,
\S\ref{sec:method:family:floors} the locality floors, and
\S\ref{sec:method:family:fen} the Finite Element Network.
\S\ref{sec:method:family:rk} describes the integration wrapper, and
\S\ref{sec:method:family:params} the parameter matching.

\subsection{The Operator Contract}
\label{sec:method:family:contract}

Every operator satisfies the same interface. It is built from
the same metadata --- one time step, eleven state channels and two
covariates --- and it consumes the same batch. It returns the full next
state in the residual form of Equation~\eqref{eq:method:residual-update}:
the predicted residual is scaled by $\Delta t$ and added to the input
state. The final layer of every architecture is initialised to zero, so
every operator starts training at exact persistence. Each module computes the
residual and the next state from one shared internal computation, so the
two cannot diverge. The integration wrapper of~\S\ref{sec:method:family:rk}
integrates exactly this residual.

No operator uses a normalisation that keeps batch statistics. The training
curriculum of~\S\ref{sec:method:training} rolls the model forward on its
own predictions without gradients but in training mode. Batch
normalisation \citep{Ioffe2015} would normalise these drifted states with
the statistics of the current batch, which would erase the very
perturbation the curriculum is meant to expose the model to. It would also
write the drifted statistics into the running estimates that evaluation
later uses, so that training and evaluation would behave as two different
operators.

The operators that work on the image grid --- the U-Net and the Fourier
Neural Operator with its local-kernel hybrid --- receive identical inputs. Each takes
sixteen input channels: the eleven state channels, $\Delta t$ broadcast as a
constant plane, the two covariates broadcast as constant planes, and two
coordinate ramps running from zero to one along each axis.
The coordinate ramps follow the CoordConv construction of \citet{Liu2018}. Because the inputs are identical, a difference between these
arms reflects the operator, not the information it receives.

\subsection{Message-Passing Graph Neural Network}
\label{sec:method:mppde}

The graph operator is the message-passing neural PDE solver (MP-PDE) of
\citet{Brandstetter2022}, the learned-stencil solver introduced
in~\S\ref{sec:background:pde-solvers:neural}. It supplies more than one arm
of the survey: it is run on two different graphs
(\S\ref{sec:method:graph}), and with fewer message-passing rounds it also
provides the locality floors of~\S\ref{sec:method:family:floors}. Several
of its design decisions --- the time handling, the output layer and the
strict one-step prediction --- also became part of the shared framework.
The original is summarised first, followed by the architecture used here
and the differences between the two.

\paragraph{The original MP-PDE.}
MP-PDE is an autoregressive neural solver for time-dependent PDEs. It
operates on a spatial graph, built on the analogy that grid points or
finite-volume cells become nodes and numerical stencils become edges. The
graph is built from a cut-off radius on regular grids, or by connecting
the $k$ nearest neighbours on irregular meshes.

The architecture follows the encode--process--decode pattern
\citep{Battaglia2018, SanchezGonzalez2020}. An encoder, a per-node
two-layer multilayer perceptron (MLP), lifts the node features into a
latent space. Its input is
$f_i^0 = \epsilon([u_i^{k-K:k}, x_i, t_k, \theta_{\text{PDE}}])$: the last
$K$ states of the node, its position, the current time and the equation
features.

The processor applies several rounds of message passing to the latent
node states; the original uses six. The message function is
$m_{ij}^m = \phi(f_i^m, f_j^m, u_i^{k-K:k} - u_j^{k-K:k}, x_i - x_j,
\theta_{\text{PDE}})$, and the node update is
$f_i^{m+1} = \psi(f_i^m, \sum_j m_{ij}^m, \theta_{\text{PDE}})$. Both
$\phi$ and $\psi$ are two-layer MLPs with skip connections and
normalisation layers. The relative position $x_i - x_j$ builds
translational symmetry into the network. The solution difference
$u_i - u_j$ lets each message act as a learned local difference operator,
a flexible learned stencil.

The equation feature vector $\theta_{\text{PDE}}$ holds the PDE
coefficients and the boundary-condition identifiers. It is injected at the
encoder and at every message-passing layer. This persistent injection is
what lets a single trained solver generalise across a family of equations;
removing it hurts most when the equation parameters vary across the
dataset.

The decoder is a shallow one-dimensional convolutional network with
weights shared across space. It treats the final hidden vector of each
node as a temporal signal and convolves along it, producing one update per
bundled step, $d_i = (d_i^1, \dots, d_i^K)$. The residual update
$u_i^{k+l} = u_i^k + (t_{k+l} - t_k)\, d_i^l$ gives the prediction for each
substep $1 \leq l \leq K$. As the step size approaches zero, the prediction
approaches the current state, which keeps the update consistent
(\S\ref{sec:background:pde-solvers:time}). The model is trained with
temporal bundling and the pushforward trick
(\S\ref{sec:background:neural-pde}). The original models have roughly one
million parameters and a hidden size of the order of 128, and they are
trained with AdamW.

The original paper names two limitations: it needs high-quality
numerical ground truth for training, and it has no formal accuracy
guarantees. A further one, not named by its authors, is that a uniform mesh
is wasteful in smooth regions and under-resolved at sharp gradients; it
motivates the moving-mesh extension of \citet{Hu2024}
(Appendix~\ref{app:mm-pde}).

\paragraph{The architecture used here.}
The forward pass consists of an encoder, a number of message-passing
rounds and a decoder. The notation follows the summary above.
Each node $i$ carries the normalised eleven-channel state $u_i$ and its
physical position $(x_i, y_i)$ in millimetres. The positions enter the
network divided by the domain size, as $(x_i / L_x,\, y_i / L_y)$.

Each node also receives a conditioning vector $\mathbf{c}_i$. In the
canonical configuration it has three entries: the interval $\Delta t$ in
years, the z-scored age and the sex of the patient. All three are
graph-level quantities, broadcast to every node of the graph. The
conditioning vector fills
the slot that the equation feature vector $\theta_{\text{PDE}}$ occupies in
the original. No governing equation or coefficients are known for GA, so
the interval and the covariates take this place. As in the original, the
vector is injected at three points: the encoder input, every message and
every node update.

The encoder maps the concatenated node input to a hidden vector,
\begin{equation}
  f_i^{0} \;=\; \epsilon\!\left(\left[u_i,\; x_i / L_x,\; y_i / L_y,\;
  \mathbf{c}_i\right]\right),
  \label{eq:method:encoder}
\end{equation}
where $\epsilon$ consists of a linear layer, layer normalisation, a ReLU
activation, a second linear layer and a final layer normalisation, with no
activation after it.

Each message-passing round $m$ computes a message along every edge from
node $j$ to node $i$ and then updates node $i$:
\begin{align}
  m_{ij}^{m} &\;=\; \phi\!\left(f_i^{m},\; f_j^{m},\; u_i - u_j,\;
    \Delta\mathbf{p}_{ij},\; \mathbf{c}_i\right),
  \label{eq:method:message}\\
  f_i^{m+1} &\;=\; \mathrm{LN}\!\left(f_i^{m} + \psi\!\left(f_i^{m},\;
    \frac{1}{|\mathcal{N}(i)|}\sum_{j \in \mathcal{N}(i)} m_{ij}^{m},\;
    \mathbf{c}_i\right)\right).
  \label{eq:method:update}
\end{align}
Here $\Delta\mathbf{p}_{ij}$ is the offset between the normalised positions
of the two nodes, $\mathcal{N}(i)$ is the set of neighbours of node $i$, and
$\mathrm{LN}$ denotes layer normalisation. The message function $\phi$ and
the update function $\psi$ each consist of two linear layers, each followed
by a ReLU activation. As in the original, the state difference $u_i - u_j$
lets the message act as a learned local difference operator. Every round
receives the raw state, the positions and the conditioning vector again, so
this information is available at every depth. As in the original, which
uses skip connections in its message-passing layers, each update ends in a
residual connection followed by a normalisation layer; only the type of
normalisation differs. The canonical configuration aggregates messages by their
mean, as written in Equation~\eqref{eq:method:update}. The canonical
configuration uses two message-passing rounds and a hidden width of 64;
larger and smaller settings are compared
in~\S\ref{sec:experiments:ablations:capacity}.

All normalisation layers are per-node layer normalisations \citep{Ba2016}. Each node is normalised over its own feature vector. No running
statistics are kept, and no nodes or graphs are coupled, so the operator is
identical in training and in evaluation, as the contract
of~\S\ref{sec:method:family:contract} requires. Before this change, when
batch normalisation was used, training and evaluation measurably behaved
as two different operators. A graph-level variant that normalises a whole
batch as one graph was avoided as well, because it would couple the
samples of a batch.

The decoder maps the final hidden vector $f_i^{M}$ to one output per
channel. It consists of a linear layer, layer normalisation and a ReLU,
applied twice, followed by a final linear layer to $C \cdot K = 11$
outputs. The final layer is bare, without normalisation or activation,
because the output is a signed and unbounded residual. The node update is
then
$u_i + \Delta t \cdot \delta(f_i^{M})$, where $\delta$ denotes the decoder;
this is Equation~\eqref{eq:method:residual-update} at node level.

In the original, the output head is a one-dimensional convolution. It
treats the final hidden vector of a node as a temporal signal and convolves
along it to emit the $K$ bundled future steps \citep{Brandstetter2022}. This
head exists to produce several time steps at once. Because the framework
predicts exactly one step ($K = 1$, \S\ref{sec:method:framework}), the
convolutional head was removed and replaced by the decoder described above.
The decoder maps the hidden vector of each node directly to the eleven
channels with a full-rank linear output layer, so every channel receives
its own independent prediction. Its final layer is initialised to zero,
which yields the persistence start of~\S\ref{sec:method:dt-residual}.

\subsection{Graph Construction on an Anisotropic Grid}
\label{sec:method:graph}

The graph on which messages travel turns out to be the most consequential
design decision of the graph solver. The modelling grid has 49 rows and
1024 columns, or 50\,176 nodes. Rows are 0.12118\,mm apart, while columns
are only 0.00568\,mm apart (\S\ref{sec:data:spatial}). Along a row, the
nodes are therefore about 21 times denser than across rows. The node
positions are stored in physical millimetres.

A $k$-nearest-neighbour graph built on these physical positions fails. The
twelve physically nearest neighbours of every node all lie in its own row:
measured over the grid, 100\,\% of the edges connect nodes in the same row
and none cross rows. Message passing on such a graph runs along rows only.
No information can cross from one row to the next at any network depth, and
the two-dimensional retina falls apart into 49 independent one-dimensional
strands.

Building the graph on integer grid indices instead of physical coordinates
restores two-dimensional connectivity. With $k = 12$, and without
self-loops, the neighbourhood of an interior node is exactly the
index-space disc of squared radius four, a diamond of radius two. It
contains the four direct neighbours, the four diagonal neighbours and the
four neighbours two steps away along either axis. The resulting graph has
602\,112 directed edges; about 33\,\% connect nodes in the same row,
50\,\% nodes one row apart and 17\,\% nodes two rows apart. About 8.5\,\%
of the nodes (4\,276), on and next to the border of the grid, do not have
the full interior neighbourhood.

This index-space graph solves the connectivity problem, but its physical
reach is lopsided. A neighbourhood that is symmetric in grid steps inherits
the 21:1 anisotropy of the grid. One hop reaches about $\pm 0.25$\,mm
across rows but only about $\pm 0.011$\,mm along a row. After the two
message-passing rounds of the canonical configuration, a node has received
information from at most four columns away, about $\pm 0.023$\,mm along the
row.

This reach can be compared with the scale on which the lesion changes.
Between two visits 180 days apart, the GA front advances a median of about
12 columns, or roughly 0.07\,mm. The upper quartile is 17 columns and the
90th percentile 23 columns. A single hop along a row therefore covers only
a small fraction of the distance the front typically moves between two
visits, and even the four columns reached after two rounds are about a
third of the median advance. The index-space graph thus solves the
connectivity problem but not the reach problem. This is why a second graph
construction was needed, one whose reach along a row matches the scale of
the lesion change.

The dilated stencil is designed to close this gap
(Figure~\ref{fig:method:stencils}). Each interior node is connected to the
nodes at row offsets $\{-1, 0, +1\}$ and column offsets
$\{0, \pm 7, \pm 14, \pm 21\}$, excluding the node itself: 20 neighbours in
total. One hop then reaches $\pm 0.121$\,mm across rows and
$\pm 0.119$\,mm along a row. The physical reach is nearly equal on both
axes, at about 0.12\,mm per hop. Along a row, one hop now spans 21 columns,
close to the 90th percentile of the per-visit front advance. The design
thus sets the reach from the physical scale of the lesion rather than
treating it as a free hyperparameter. Chapter~\ref{ch:experiments} tests
this choice against smaller and larger reaches.

The dilated stencil replaces only the edge set. The network, its weights
and every other component stay unchanged, and the stencil adds no
parameters.

\subsection{Dense Operators: U-Net, FNO and a Local-Kernel Hybrid}
\label{sec:method:family:dense}

The first dense operator is a U-Net \citep{Ronneberger2015}. The
original was designed for biomedical image segmentation. It consists of a
contracting and an expansive path. Each contracting step applies two
unpadded $3 \times 3$ convolutions, each followed by a ReLU, and then a
$2 \times 2$ max pooling with stride two; the number of feature channels
doubles at each downsampling step. Each expansive step upsamples, halves the
channels with an up-convolution, concatenates the correspondingly cropped
feature map from the contracting path, and applies two further $3 \times 3$
convolutions. A final $1 \times 1$ convolution maps to the output classes.
\citet{Gupta2023} study modernised U-Nets as PDE surrogates and
describe them as handling local and global information through
the down- and up-sampling paths.
In the GA domain, \citet{Salvi2025} predict future lesion growth with a
two-dimensional U-Net on fundus autofluorescence images.

The U-Net used here departs from the original in four ways. First, each
convolution is followed by group normalisation with a single group before
the ReLU; the original uses no normalisation.
With one group, group normalisation normalises each sample over all its
channels and positions and keeps no batch statistics \citep{Wu2018}. With
nine such blocks --- an input stage, four downsampling and four upsampling
stages --- the network has 18 normalised convolution sites. Second, pooling
is anisotropic. The factors (rows, columns) are $(1, 2)$, $(1, 2)$,
$(2, 2)$ and $(2, 2)$, so the grid shrinks from $49 \times 1024$ through
$49 \times 512$, $49 \times 256$ and $24 \times 128$ to $12 \times 64$. Rows
are pooled four times and columns sixteen times, which reduces the 21:1
aspect of the grid to about 5:1 without removing it. The schedule was
deliberately not tuned further, because a comparison model whose geometry
has been optimised against this dataset would be a weaker control, not a
stronger one. Third, upsampling is nearest-neighbour instead of an
up-convolution, and the output has the grid size of the input. Fourth, the
final $1 \times 1$ layer is zero-initialised and returns a residual rather
than class scores. A base width of five gives 83\,081 parameters.
% Width-32 U-Net (3,354,347 parameters, "capacity control") removed
% 2026-09-28 (author: a single 50x arm against parameter-matched models does
% not answer the capacity question; separate capacity experiments planned).

The second dense operator is the Fourier Neural Operator (FNO) of \citet{Li2021}. The input is first lifted to a wider representation by a local
map. Each layer then combines a local linear transform with a non-local
integral operator and applies a nonlinearity. The integral operator
transforms its input to Fourier space, multiplies the retained low modes by
learned complex weights, and transforms back. Modes above a threshold are
truncated; both the low positive and the low negative frequencies are kept.
A local projection maps the result to the output. The paper shows that the
Fourier layers are invariant to the discretisation, and that truncation does
not limit the output to the retained modes, because the nonlinearities and
the projection recover higher frequencies. For its two-dimensional problems,
the original uses four Fourier layers, ReLU activations with batch
normalisation, 12 modes per dimension and a width of 32. It notes that the
local linear term helps the model handle non-periodic boundaries.

The FNO used here keeps four blocks, each a spectral convolution plus a
pointwise $1 \times 1$ path, and departs from the original in the
following respects. It uses GELU activations between blocks instead of ReLU,
and no normalisation. It retains 14 modes per axis instead of 12, and its
width is 5 instead of 32, which gives 79\,160 parameters. The output passes
through a $1 \times 1$ convolution to 32 channels, a GELU and a
zero-initialised $1 \times 1$ projection. The domain here is a crop, not a
periodic physical domain (\S\ref{sec:data:spatial}). This thesis therefore
zero-pads the field by about one eighth per axis before the transform, from
$49 \times 1024$ to $56 \times 1152$, and crops it back after the spectral
blocks; the original relies on the local linear term instead and does not
pad. The mode count follows from the geometry. The physical domain is nearly
square ($5.94 \times 5.82$\,mm), so equal mode counts give nearly equal
physical bandwidth on both axes --- the property the index-space graph
of~\S\ref{sec:method:graph} lacks. Dividing the padded extent by the highest
retained mode index, 13, gives a finest retained wavelength of about
0.52\,mm across rows and 0.50\,mm along columns. The mode count was not
ablated.

The third dense operator is a local-kernel hybrid.
\citet{LiuSchiaffini2024} observe that global operations in Fourier
space are prone to over-smoothing and may miss local details. They add
localised operators in parallel to the Fourier layers and the pointwise
path. Their differential kernels subtract the kernel mean and rescale by the
reciprocal grid width, so that the convolution converges to a differential
operator as the grid is refined; their localised integral kernels use
discrete-continuous convolutions. The hybrid used here is the simplest
instance of this idea. It widens the pointwise $1 \times 1$ path of each FNO
block to an unconstrained $3 \times 3$ convolution, so a local path runs in
parallel with the spectral one. Unlike the original, it operates at a single
training resolution, without mean subtraction, without rescaling and without
discrete-continuous convolutions; it is therefore not the
resolution-consistent operator of that paper. The spectral path keeps
global support and the local path gains one ring of neighbours, at a cost
of 800 parameters (79\,960 in total). With a kernel size of one, the model
reduces exactly to the plain FNO.

\subsection{The Finite Element Network}
\label{sec:method:family:fen}

The Finite Element Network (FEN) of \citet{Lienen2022} builds the
update from a finite-element discretisation of an unknown PDE. It is the only
operator whose output is defined as a time derivative by
construction rather than as a next state. This is a property of the
architecture. It is not a claim that the trained model behaves as a valid
continuous-time system, which is tested in Chapter~\ref{ch:experiments}.

The original uses a Galerkin method with the P1 basis of piecewise-linear
hat functions, by default on a Delaunay triangulation of the observation
points. The resulting system involves the mass matrix of inner products
between basis functions, which is lumped by row-wise summation --- a
standard approximation for time-dependent problems that makes its inversion
trivial. The inner products are factored so that a network, the free-form
term, predicts one coefficient per cell, vertex and feature from the time,
the cell centre, the local vertex coordinates and the vertex features. The
transport variant, T-FEN, adds a convection term. It starts from the
conservative form $-\nabla \cdot (v u)$, applies the product rule and
assumes a divergence-free velocity, which leaves the advective form
$-v \cdot \nabla u$. A second network predicts one velocity per cell and
feature; since the velocity is constant within each cell, it is
divergence-free there, but not across cells. Both networks are tanh MLPs,
and the resulting ODE is solved with the adaptive dopri5 solver.

The FEN used here triangulates the regular grid by splitting every grid
cell into two right triangles, which gives 98\,208 triangles over the
50\,176 nodes; each node belongs to one, two, three or six triangles. The
mass matrix is lumped as in the original. On this equal-area lattice the
lumped assembly is exactly a mean over the triangles adjacent to a node.
On a uniform mesh, the FEN is therefore a message-passing network over
triangle hyperedges with mean aggregation, and the finite-element machinery
only makes a difference at the boundary. The free-form term is a tanh MLP
of depth four and width 96, without normalisation and with a
zero-initialised head. It receives the three vertex states of a triangle, a
triangle-type indicator for the two triangle orientations, the covariates
and optionally the normalised triangle centre, and it outputs one
coefficient per vertex and channel.

The transport term is a second MLP that predicts one velocity per triangle
and channel, in millimetres per year. The assembled operator is the
advective form $-v \cdot \nabla u$ with a velocity that is constant within
each triangle, as in the original. Neither the original nor this
implementation makes the velocity divergence-free across triangles, so
reading it as a physical advection speed rests on an assumption the model
does not enforce globally. The gradient coefficients are assembled in grid
units, so the 21:1 axis imbalance never reaches the MLPs; only the velocity
conversion uses millimetres. The transport term runs on its own coarser mesh,
built on every seventh column (97\,632 triangles), while the free-form term
uses the full-resolution mesh. This coarser mesh is the finite-element
counterpart of the dilated stencil of~\S\ref{sec:method:graph}.

The implementation departs from the original in the following points. A
regular lattice replaces the Delaunay triangulation. A triangle-type
indicator replaces the local vertex coordinates, which on this lattice take
only two forms. The covariates are added as inputs. The time is not an
input, so the learned dynamics are autonomous, a variant the original paper
explicitly allows. Integration uses a fixed-step scheme instead of the
adaptive dopri5 solver. The advective form and the per-cell velocity are the
same as in the original; the energy-conserving form of the transport
operator described below is a further departure.

One evaluation of the time derivative only couples nodes that share a
triangle, so spatial reach has to come from sub-steps. The FEN is therefore
always run inside the Runge--Kutta wrapper of~\S\ref{sec:method:family:rk},
with classical RK4 and a fixed physical step of 45 days; $\Delta t$ sets
only the integration horizon. RK4 is used because, in the interior of the
lattice, the assembled transport operator has a purely imaginary spectrum:
an explicit Euler step would amplify every mode for any non-zero velocity,
whereas RK4 has a stability interval on the imaginary axis. It remains
stable only while the velocity times the step, the Courant number in the
sense of the stability condition of~\citet{Courant1928}, stays below a limit
of about 2.4 for this stencil.

\paragraph{Two forms of the transport operator.}
Two forms of the assembled transport operator were trained. The first is
the Galerkin form described above, as in the original. At a constant
velocity and away from the edge of the domain, it conserves a discrete
energy of the state, the mass-weighted sum of squares $u^\top M u$, as
pure transport should: content is moved, not created. At the edge of the
crop, and for a velocity that varies from triangle to triangle, it does
not. No flux term is assembled at the boundary, so transported content
accumulates there, and the operator has modes that grow instead of
travelling. The second form removes this defect. It keeps only the
energy-conserving part of the Galerkin operator $L$,
\begin{equation}
  L_{\text{skew}} \;=\; \tfrac{1}{2}\left(L - M^{-1} L^\top M\right),
  \label{eq:method:fen-skew}
\end{equation}
which conserves $u^\top M u$ for any per-triangle velocity, including at
the edge, where it acts as a closed wall. In the interior and at a constant
velocity, the two forms coincide. The energy-conserving form adds no
parameters and no measurable cost.

The Galerkin form turned out to be unstable, and the T-FEN reported in
Chapter~\ref{ch:experiments} uses the energy-conserving form; the Galerkin
runs are reported in~\S\ref{sec:experiments:validity:tfen}. \emph{Unstable}
has a specific meaning here. During evaluation, every model is run freely:
it predicts the next visit from its own previous prediction, over each
eye's whole follow-up of up to about six years, without any ground truth
fed back. A run is called stable if, in this free-running rollout, the root
mean squared error of the mask channel and of the layer channels, both in
normalised units, stays at or below 5 on at least 19 of its 20 late
epochs. The normalised values of a correct prediction lie within a few
units of zero, so an error above 5 means that the rollout has left the
range of plausible states; in an unstable run it keeps growing, up to
values of several thousand. The criterion was fixed before the
energy-conserving form was trained.

\subsection{Fixed-Step Runge--Kutta Integration}
\label{sec:method:family:rk}

The Runge--Kutta wrapper is not a backbone. It is placed around any
backbone and changes only how the backbone's output is turned into the next
state. It adds no parameters.

\paragraph{Euler and RK4.}
The canonical update of Equation~\eqref{eq:method:residual-update} is one
explicit Euler step: the operator is evaluated once, at the current state,
and its output is applied over the whole interval $\Delta t$. A Runge--Kutta
scheme evaluates the operator several times within the interval, at
intermediate states, and combines the results. The classical fourth-order
scheme (RK4), used in every reported run, evaluates it four times per step
and takes a weighted average \citep{Butcher1987, Hairer1993}. The interval
can also be split into several sub-steps, each of which is one RK4 step.
The wrapper stores each scheme as a Butcher tableau. The sub-step length is
set per graph, either as $h = \Delta t / n$ or from a physical step length
in days, with the number of sub-steps rounded up from the ratio of the
interval to that length. An eye is therefore integrated with the same steps
whether it is batched with others or evaluated alone; graphs with shorter
intervals take zero-length steps until the longest interval in the batch is
complete. As a unit check, the observed convergence orders on the test
problem $\mathrm{d}u / \mathrm{d}t = -\lambda u$ are 0.99, 2.04, 2.04 and
4.35 for the Euler, midpoint, Heun and RK4 schemes, close to their nominal
orders of one, two, two and four.

\paragraph{The autonomous field.}
Inside the wrapper, the $\Delta t$ entry of the operator's conditioning
vector is set to zero. The operator then no longer knows how long the
interval is. Its output only states how fast the state is changing at the
current moment, and the integrator alone decides how long this rate is
applied. The update itself is not zero: the state still changes by the
integrated rate. In this reading the wrapped model is a Neural ODE in the
sense of \citet{Chen2018}. Positions, graph edges and covariates stay fixed
across the stages of one step. The wrapper requires the $\Delta t$-multiplied
residual form of Equation~\eqref{eq:method:residual-update}. If the
sub-step length is fed to the operator in place of zero, the wrapper acts
instead as a learned Runge--Kutta integrator, which reduces to the
canonical operator for a single Euler step.

\paragraph{Why the wrapper exists.}
It has three uses. First, the finite-element network outputs a rate and
needs an integrator (\S\ref{sec:method:family:fen}); since one evaluation
couples only nodes that share a triangle, its spatial reach grows with the
number of evaluations. Second, it allows the integration order to be tested
on its own: the same backbone trained with one Euler step and with RK4
(\S\ref{sec:experiments:ablations:time}). Third, it allows the question of
whether a model describes a continuous process to be tested.

\paragraph{Jump and continuous time.}
The canonical model is trained as a single jump: it learns which state
follows after an interval of length $\Delta t$, in one step. Nothing
requires that two jumps of length $\Delta t / 2$ lead to the same state as
one jump of length $\Delta t$. A continuous-time model must satisfy exactly
this: splitting the interval into more or finer steps must not change the
answer. \citet{Ott2021} show that a model trained with an overly coarse step
can reach high accuracy and still lose this property, and they test it by
evaluating the trained model with solvers of equal or smaller
discretisation error and checking whether its predictions stay the same.
\citet{Krishnapriyan2023} make the same point for learned models of
physical systems. Because any trained backbone can be integrated with
different schemes and step counts after training, the wrapper makes this
solver-swap test possible. Its outcome is reported
in~\S\ref{sec:experiments:validity:swap}: the canonical model fails it,
whereas the same network trained under the RK4 wrapper passes it, as does
the finite-element network. A continuous-time model can therefore be
obtained by training with the integrator, but in this survey it is not
more accurate than the single jump (\S\ref{sec:experiments:ablations:time}).

\section{Conditioning: Patient Covariates}
\label{sec:method:covariates}

Every window carries two patient-level covariates, the age of the patient
at the start visit and the sex. Their extraction and encoding are described
in~\S\ref{sec:data:covariates}. This section describes how they enter the
operators. Both covariates are graph-level quantities: a visit has one
value of each, and that value is shared by all $50\,176$ grid positions.
Along the trajectory of one eye, the sex is constant and the age advances
only with the elapsed time. Because the covariates carry no spatial
information, they can only shift the prediction of an operator as a
whole. They cannot point to a location on the grid or shape the lesion
boundary locally.

The covariates are included because age and sex are plausible modulators
of how fast GA progresses. Together with $\Delta t$, they fill the slot
that the equation features $\theta_{\text{PDE}}$ occupy in MP-PDE, since
no governing equation with known coefficients exists for GA
(\S\ref{sec:method:mppde}). How they enter the forward pass depends on the
operator. In the graph network, they are two of the three entries of the
conditioning vector, broadcast to every node and injected at the encoder
input, into every message and into every node update
(\S\ref{sec:method:mppde}). The per-pixel and one-hop floors are truncated
graph networks and receive them in the same way
(\S\ref{sec:method:family:floors}). In the dense grid operators --- the
U-Net, the Fourier Neural Operator and the local-kernel hybrid --- each
covariate is an extra input channel holding a constant plane
(\S\ref{sec:method:family:contract}). The free-form network of the Finite
Element Network receives them as additional inputs
(\S\ref{sec:method:family:fen}). Inside the Runge--Kutta wrapper, they are
held fixed across the stages of one integration step
(\S\ref{sec:method:family:rk}).

The covariates are enabled in the canonical configuration of every
operator.

\section{Training}
\label{sec:method:training}

Everything in this section is shared by every operator of the survey
(\S\ref{sec:method:family:contract}), and Table~\ref{tab:method:hparams}
lists the settings. The objective, the curriculum and the
optimisation settings do not change between arms, so that a difference
between two arms can be attributed to the operator.

\subsection{Objective}
\label{sec:method:training:loss}

The loss is computed on the normalised state (\S\ref{sec:data:normalization})
and has two terms, a channel-weighted mean squared error (MSE) and a
soft-Dice term on the mask channel:
\begin{equation}
  \mathcal{L} \;=\; \frac{1}{\bar{w}} \sum_{c=0}^{10} w_c\,
  \mathcal{L}_{\text{MSE}}^{(c)} \;+\; \lambda_{\text{Dice}}\,
  \mathcal{L}_{\text{Dice}},
  \label{eq:method:loss}
\end{equation}
where $\mathcal{L}_{\text{MSE}}^{(c)}$ is the mean squared error of
channel~$c$, $w_c$ its weight and $\bar{w}$ the mean of the weights.
The mask channel ($c = 0$) has the weight $w_0 = 5$, and each of the ten
layer channels has the weight $w_c = 1$. Dividing by the mean weight keeps
the scale of the term comparable to an unweighted MSE. The mask is the
clinical target. The layer channels are auxiliary targets, but the
operator must still predict them, because they are part of the next state
that is fed back during a rollout.

The second term is a soft-Dice loss on the mask channel
\citep{Milletari2016}, with the weight $\lambda_{\text{Dice}} = 5$. It addresses a property
of the data. Between two consecutive visits, almost all mask pixels are
unchanged, so a plain MSE is dominated by static pixels and gives little
gradient at the moving lesion boundary. A model trained on it can settle on
copying its input. The soft-Dice term restores gradient in the band around
the binarisation threshold, which is where the boundary lies. Unlike the
original, which scores a segmentation probability map, it is applied here
to a regression output. The prediction $p$ of the mask channel is first
turned into a soft mask,
\begin{equation}
  p_{\text{soft}} \;=\; \sigma\!\left(s\,(p - \tau)\right),
  \label{eq:method:soft-mask}
\end{equation}
where $\sigma$ is the logistic sigmoid, $s = 2$ the sharpness and $\tau$
the physical threshold of 0.5 mapped into normalised space. The evaluation
uses the same mapping (\S\ref{sec:data:normalization}), so the loss and the
metric agree on where the threshold lies. With the hard-thresholded target
mask $t$, the term is
$\mathcal{L}_{\text{Dice}} = 1 - 2 \sum p_{\text{soft}} t \,/\,
(\sum p_{\text{soft}} + \sum t)$.

The soft-Dice term is computed per eye and then averaged over the batch.
A Dice score is a ratio of sums. If the sums were pooled over the whole
batch, the gradient for one eye would depend on which other eyes it was
batched with. Scoring per eye also matches the evaluation, which scores
each eye separately before averaging. One side effect is accepted. The
sigmoid of Equation~\eqref{eq:method:soft-mask} does not saturate at the
physical mask values, so the term stretches the raw mask regression about
the threshold. This cannot change a thresholded prediction, but it changes
the raw error of the mask channel. It is one reason why the evaluation does
not compare operators on raw errors (Chapter~\ref{ch:experiments}).

Two further options exist in the implementation and are off in every
reported run. First, the loss can exclude grid positions whose target
equals the fill value of the crop padding (\S\ref{sec:data:spatial}), from
both terms. Since this option is off, the padded positions are regressed at
full weight. Second, a monotonic-growth penalty can be added, which
penalises a decrease of the mask where the previous state is atrophic. Its
weight is zero for every operator of the comparison;
\S\ref{sec:method:dt-residual} explains why no monotonic constraint is
imposed, and~\S\ref{sec:experiments:ablations:loss} tests the penalty. The same loss is used in training and in
validation.

\subsection{Time-Budgeted Pushforward Curriculum}
\label{sec:method:training:curriculum}

The operators are trained with the pushforward trick of
\citet{Brandstetter2022} (\S\ref{sec:background:neural-pde}): the model is
rolled forward on its own predictions without gradients, and only the
final step is supervised. The original counts the depth of this rollout in
steps. With irregular visit intervals (\S\ref{sec:data:temporal}), a step
count is not a comparable quantity: two steps can mean 180 days for one eye
and 720 days for another. The framework therefore counts the depth in
elapsed days.

Each training pass draws a time budget $B$ uniformly from
$\{0, 1, \dots, \min(e, U)\} \times 180$ days, where $e$ is the current
epoch. The base of 180 days is the modal visit interval of the cohort
(\S\ref{sec:data:temporal}). Every reported run uses $U = 2$, so the
largest budget is 360 days, which matches the one-year evaluation anchor.
Because of the $\min(e, U)$, the horizon ramps in over the first $U$
epochs; after that, budgets of 0, 180 and 360 days are drawn with equal
probability. A budget of zero gives a plain one-step pass on observed
inputs.

For a given budget, only start windows that can realise it are sampled.
The chain of consecutive visits from such a window must reach at least $B$
days in total, and its first interval must not exceed $B$. If an eye has no
such window, sampling for that eye falls back to all of its windows.
% Checked 2026-10-01 in utils/utils.py (_rebuild_valid_t0s): the restriction
% applies only for B > 0; at B = 0 any window is drawn.
The number of unrolled steps for each eye then follows an undershoot rule:
it is the largest $n$ for which the $n$ rolled intervals and the final,
supervised interval together stay within $B$. The chain never overshoots
the budget, so eyes on different visit schedules are trained to the same
elapsed horizon. This is also why the base is 180 days and not the
shortest interval of 90 days. Under the undershoot rule, a 90-day budget
can never chain two visits (\S\ref{sec:data:temporal}), and the curriculum
would never unroll at all.

Within a batch, the eyes are grouped by their number of unrolled steps.
Each group is rolled forward $n$ steps without gradients: at every step,
the next window of the eye is fetched and its input state is replaced by
the model's own prediction. All channels are rolled, including the
predicted mask. An eye whose sequence ends is dropped from the chain. The
group then receives one forward pass with gradients, and the loss is taken
against the observed next state. The group losses are weighted by the
share of the batch each group holds and combined. The rollout runs in
training mode, which is why no operator may use batch statistics
(\S\ref{sec:method:family:contract}).

\subsection{Optimisation}
\label{sec:method:training:optim}

All operators are trained with AdamW \citep{Loshchilov2019}, a
learning rate of $2 \times 10^{-3}$ and a weight decay of
$1 \times 10^{-2}$ on all trainable parameters. The learning rate is
multiplied by 0.4 from epoch 5 on and again from epoch 20 on, counting
epochs from 0 (the first five epochs run at the initial rate).

Training runs for 30 epochs. One epoch consists of 20 passes. In each pass,
a new time budget is drawn, and every training eye contributes one randomly
chosen start window that can realise it. The batch size is four eyes.
Because the number of training eyes differs between the folds
(\S\ref{sec:data:splits}), an epoch has between 280 and 320 optimiser
steps, depending on the fold.

Gradients are clipped to a norm of 1.0, separately for each trainable
module: each module is clipped by its own gradient norm, so that a large
gradient in one module cannot shrink the updates of another. For the
single-network operators of the main comparison, this amounts to one clip
over the whole model. The separation matters for the moving-mesh extension
of Appendix~\ref{app:mm-pde}.

Every reported run uses the seed 42; replication runs with the seed 7 are
reported in Chapter~\ref{ch:experiments}. The model is validated on the
held-out fold after every epoch (\S\ref{sec:data:splits}); which epochs
enter the reported numbers, and why, is set out
in~\S\ref{sec:experiments:protocol}.

\section{Implementation Details}
\label{sec:method:implementation}

The framework is implemented in Python with PyTorch 2.4.1 and CUDA 12.1
\citep{Paszke2019}. The graph operators use PyTorch Geometric 2.6.1
\citep{Fey2019}.
% Versions read from the cluster container
% pytorch-2.4.1-cu121-cudnn9-runtime.sif on 2026-10-01 (2.4.1+cu121, 2.6.1).
All dependencies are pinned in a fixed container image. Every reported run
was trained on a single NVIDIA RTX A6000 GPU on a cluster managed by
Slurm, and the five folds of an experiment are submitted together as a job
array.

The windows of each fold are precomputed once before training. This step
performs the crop and pad, the normalisation and the extraction of
$\Delta t$ and the covariates, and it builds the index-space neighbour
graph. Because the grid is the same for every visit, one graph serves all
windows. The dilated stencil of the canonical graph network
(\S\ref{sec:method:graph}) is built at run time from the grid indices
rather than stored. All precomputed data are held in memory during
training.

All random number generators --- those of Python, NumPy, PyTorch and CUDA
--- are seeded, and deterministic cuDNN algorithms are enforced. The data
loader runs in the main process. This is required, because the curriculum
changes the sampling restriction of the dataset at every pass, and a change
made in the main process would not reach separate worker processes. Even
so, repeated runs of the same configuration do not give identical results
on the GPU. Chapter~\ref{ch:experiments} quantifies this run-to-run
variation, and it defines the noise floor against which every comparison
is read.
